GENO0.5

A programming language for code you didn’t write.

Geno is a statically typed, functional-first language for programs written with LLMs. Functions carry examples that run as tests, every block closes by name, and files, the network and other processes stay off until you grant them. It runs directly and compiles to Python and JavaScript.

$ pip install geno-lang
Open the playground →

Needs Python 3.10–3.13. Geno is pre-1.0, so the language may still change.
Read the datasheet ↓

1Features

  • Executable example clauses, required on ordinary functions
  • requires and ensures contracts, compiled into every backend
  • Named block endings: end func, end if, end match
  • Exhaustive pattern matching over algebraic data types
  • Capability-gated effects: files, network, processes, environment, clock
  • Static types with local inference, generics and traits
  • Runs directly; compiles to Python and JavaScript
  • Next-token constraints for guided generation (research)

2Applications

  • Command-line tools and automation on Python or Node.js
  • Browser dashboards, internal tools and small games
  • Hosted request handlers behind geno serve
  • Code paths written or repaired by coding agents

3Description

Models are good at writing code that looks right. Geno is designed so that looking right is not enough. A function states its types, carries examples that run, and closes every block by name. A program cannot grant itself access to files, the network or other processes; the person running it grants each capability by name.

The result reads like a small, strict functional language: immutable by default, with algebraic data types, Result and Option for errors, pipelines and traits. The checker makes sure every case is handled, and geno test makes sure every example still holds.

Geno is in public preview. The parser and type checker are stable; the language surface may change before 1.0.

4Anatomy of a functionPin configuration and functions

A Geno function is a component with a published interface. Its signature is the pinout, its examples are the test conditions, and its last line says exactly what it closes.

Table 4-1. Pin functions of score_label
PinNameTypeDescription
1score: IntIParameters always carry types. Local let bindings may be inferred.
2caps: nonePEffects. The body uses no capability, so it runs anywhere. A function that read files would run only where --cap fs is granted.
3-> StringOReturn type, required. Errors are values, Result[T, E] and Option[T], never null.
4exampleTExecutable specification, run by geno test. Required on ordinary functions; main, async functions, app lifecycle hooks and @untested functions are exempt.
5requiresCPrecondition, checked on every call in the interpreter, Python and JavaScript. ensures checks result.
6end funcTNamed terminator. A mismatched end fails on its own line, so generated structure cannot drift silently.

I = input, O = output, P = permission, C = contract, T = checked by the toolchain. Pin numbers match Figure 4-1.

8Capabilities and limitsSpecifications

    
Generated code runs with what the person running it allows, and within limits they can see.


    

      
8.1CapabilitiesIsolation characteristics

      
Most computation is always available. Regular expressions and anything that reaches outside the program need a capability. Plain geno run grants print, clock and random; every other capability is granted by name by the person who runs the program, and a program cannot grant itself anything.

      

        

          Table 8-1. Capabilities
          
CapabilityUnlocksPlain geno run(1)

          
            
printConsole outputGranted

            
clockTimestamps, timing, sleep_msGranted

            
randomRandom numbersGranted

            
fsRead, write and list filesDenied

            
httpOutbound HTTP and HTTPSDenied

            
envEnvironment variables, CLI argumentsDenied

            
processRun other programsDenied

            
regexRegular expressionsDenied

            
stdinStandard inputDenied

            
serveListen for HTTP requestsDenied

          
        

      

      
(1) geno run app.geno compiles to Python and runs it in an isolated process with print, clock and random. Every other call is refused where it happens, naming the capability it needs (reported as E412 by --json and the embedding API).

      

        
Granting a capability


$ geno run --unsafe --cap print,fs app.geno   # direct interpreter
$ geno run --json --cap print,env app.geno    # embedding API, JSON result
$ python app.py --cap print,fs                # compiled Python

        
--cap grants exactly the capabilities it lists, so name print too if the program prints. The default lane refuses --cap, so a grant can never quietly switch off process isolation. --unsafe means no process isolation; capability checks and step limits still apply.

        
Granted is not unlimited. With fs, paths resolve inside the project’s filesystem roots and absolute paths are rejected; with http, loopback and private-network addresses are refused and responses are read through size limits. Generated JavaScript is trusted code, not a sandbox. See the security policy.

9The languageFeature description

    
A small, strict functional language: immutable by default, with algebraic data types, Result and Option for errors, pipelines and traits. Each feature below is there because it turns a plausible mistake into a reported one.


    

      

        
9.1Named block endings

        
A model writes one token at a time. With braces, the end of a loop and the end of a function are the same character, and losing count produces code that parses and means something else. In Geno every block closes by name, so a mistake fails at the exact line.

        
Because openers and closers always pair, Geno can say at any point in a partial program what is still open. That is what geno constrain reports, and what a constrained decoder can use to keep a model’s block structure intact.

        
Stack values in Figure 9-1 come from geno.constraints.get_unclosed_blocks on each prefix.

      

      

        

          
Figure 9-1. A model streaming Geno. Open blocks, innermost first.

          
        

        

        

        

      

    


    

      

        
9.2Exhaustive matching

        
Algebraic data types describe every shape a value can take, and the checker holds every match to all of them. Add a variant later and each match that ignores it stops compiling, naming the case it missed.

        
Click an arm to remove it or put it back. The output is geno check.

        
A wildcard _ also satisfies the checker. It covers every case, including variants added later, without naming them, so use explicit arms where a new case should force a decision.

      

      

        

          
Figure 9-2. Click a match arm to toggle it.

        

        

        

      

    


    

      

        
9.3Errors are values


func parse_port(arg: String) -> Result[Int, String]
  example "8080" -> Ok(8080)
  example "http" -> Err("not a number: http")
  match parse_int(arg) with
      | Some(n) -> return Ok(n)
      | None -> return Err("not a number: " + arg)
  end match
end func

        
Result and Option replace null and unchecked exceptions. The ? operator returns an error early.

      

      

        
9.4Pipelines


func squares_of_evens(xs: List[Int]) -> List[Int]
  example [1, 2, 3, 4, 5] -> [4, 16]
  return xs
      |> filter(_, fn(x: Int) -> x % 2 == 0)
      |> map(_, fn(x: Int) -> x * x)
end func

        
Data flows left to right; _ marks where the value goes. List comprehensions cover the rest.

      

      

        
9.5Traits


type Planet = Planet(name: String, moons: Int)

trait Describable
  func describe(self: Self) -> String
end trait

impl Describable for Planet
  func describe(self: Planet) -> String
      example Planet("Mars", 2) -> "Mars has 2 moons"
      return f"{self.name} has {self.moons} moons"
  end func
end impl

        
Shared behaviour without inheritance. Methods carry examples like every other function.

      

      

        
9.6Async, data, modules


async func page_size(url: String) -> Int
  return length(http_fetch(url))
end func

func main() -> Int
  let size = await page_size("https://example.com")
  let rows = csv_parse_with_headers("name,age\nAda,36")
  return size + length(rows)
end func

        
async and await, built-in JSON, CSV and TOML, and modules with explicit export.

      

    

  


  
  

    
10How Geno runsDetailed description


    

      
10.1ToolchainFunctional block diagram

      
One front end, three ways to execute. Before any backend sees the program, the checker holds every match to all of its cases and works out which effects each function has. geno test runs the examples; geno compile does not, so keep geno test in CI.

      
    


    

      
10.2TargetsDevice functional modes

      
One program, four places to run. A project declares its targets in geno.toml, and geno check --target rejects builtins a target does not provide before anything runs.

      

        

          
MODE A
python-cli
Beta

          
Command-line tools and automation. Multi-module projects compile to one Python file that runs without Geno installed.

          
$ geno compile app.geno -o app.py
$ python app.py --cap print,fs

        

        

          
MODE B
node-cli
Beta

          
The same program on Node.js, as a script or ES module with source maps and type declarations. Trusted execution only.

          
$ geno compile app.geno --target js -o app.js
$ node app.js --cap print

        

        

          
MODE C
browser
Beta

          
App-mode programs with init, update and render build to static files with canvas, keyboard and mouse.

          
$ geno build Main.geno -o dist/
$ geno dev   # live reload

        

        

          
MODE D
python-hosted
Beta

          
An HTTP runtime with isolated execution, authentication, rate limits and Prometheus metrics.

          
$ geno serve
# POST /run · GET /healthz · GET /metrics

        

      

      

        
        

          
Execution boundary

          
Generated JavaScript is trusted code. In Mode B, --cap selects which Node.js APIs are wired up; it does not sandbox the artifact. Run untrusted programs through geno run, which isolates the process, or behind geno serve. The in-process embedding API applies cooperative limits only.

        

      

    

  


  
  

    
11PerformanceTypical characteristics

    
Compiled Geno against hand-written Python on the same 53 problems. Geno keeps its safety checks in the compiled output, guarding integer growth and collection sizes, and pays for them here.

    

      

        
1.60×median time vs Python

        
84.9%of problems at or under 2×

        
0.92×best case, mutual recursion

        
2.84×worst case, list building

      

      
    

    

      
What we don’t claim

      
    
        
  • That models write correct Geno more often than correct Python. The repository defines an LLM-correctness benchmark; no frontier-model results are published yet. Why we wait.
    • 
        
  • That passing examples prove a function correct. They are evidence at the points they name, and only as good as the points chosen.
    • 
        
  • That compiled Geno is as fast as Python. It keeps its safety checks and pays for them: a median of 1.60× on the problems above.
    • 
        
  • That generated JavaScript is a sandbox. It is trusted code; --cap chooses which APIs are wired up.
    • 
        
  • That constrained decoding improves models. Block-structure validation of a prefix works; it has not been benchmarked against real models.
    •

12.2Prompting a modelDesign requirements for generated code

      

        

          
Models arrive knowing Python and JavaScript. These rules cover the mistakes they make most often in Geno. Paste them into a system prompt, then let geno test report anything they miss.

          
    
            
  • let mut var
    • 
            
  • True true
    • 
            
  • "a" ++ "b" "a" + "b"
    • 
            
  • end: Int stop: Int
    • 
            
  • clamp(5, 0, 10) clamp(value: 5, lo: 0, hi: 10)
    • 
          

        

        

          
system-prompt.txt


You are writing code in Geno, a statically typed, functional-first language.
- Immutable: let x = 5. Mutable: var count = 0.
- Parameters and return values need type annotations.
- Booleans are lowercase: true, false.
- Concatenate strings with +. Integer division truncates: 7 / 2 = 3.
- Close blocks by name: end func, end if, end for, end while, end match.
- Write then after if conditions and do after for and while.
- Every function except main needs at least one example clause.
- Functions with 3 or more parameters take named arguments.
- Use Option[T] instead of null and Result[T, E] for errors.
- Do not name anything end, in, with, type, or a Python builtin.
