## Motivation

[RC.4](https://github.com/davidiach/geno-lang/releases/tag/v0.6.0-rc.4)
completed its local and hosted qualification, publishing workflow, public
wheel/sdist hash checks and fresh installed-product verification.

After its source was cut, [PR #222](https://github.com/davidiach/geno-lang/pull/222)
merged at 2026-10-25 08:00:02 UTC as
`8c12a5e389aa394bee1a9c37e46d3325818b4f17`. It raises the setuptools
build minimum and updates MSAL publishing tooling. These dependency/build
changes are absent from RC.4. Proposal 0015 explicitly requires another
versioned RC and a new baseline amendment before including such changes in stable.

Reverting the security fixes to preserve the older baseline would discard
another accepted change. Silently absorbing them would exceed the existing
promotion decision. A separately qualified RC.5 preserves both decisions.

## Guide-Level Design

RC.5 keeps the frozen Geno language, diagnostics, APIs, capabilities, backends
and target support from RC.4. It introduces no Geno source migration.
It requires a patched Python build backend and patched VS Code development
publishing tooling. A separately gated stable version remains 0.6.0.

Stable promotion may add only the already-permitted governance, version and
documentation delta after RC.5 qualification. No performance budget, sample,
calibration, security boundary or supported-target policy changes.

## Reference Design

Retain the exact implementation from #222:

- Python `build-system.requires` uses `setuptools>=84.1.0`, matching the
  existing release lock. This closes the lower build-minimum gap; RC.4's tested
  builds used 84.1.0 but its declared minimum was 82.0.1.
- Scope the npm override to `@azure/identity -> @azure/msal-node`, selecting
  MSAL Node 7.1.1 and its required nested msal-common 16.14.3.
- Preserve the separate msal-common version required by msal-browser.
- Retain regression tests for the setuptools floor and every MSAL lockfile copy.
- Retain the documented override-removal condition in the extension README.

The override crosses Azure Identity's declared major-version range. Initialization,
extension tests, npm 10/npm 11 installation and VSIX packaging passed during #222
review. Live authenticated VSCE publishing was not tested and is not claimed.
Repeat relevant installation, initialization, audit and packaging validation on
the final RC.5 candidate. Runtime VSIX contents must continue excluding VSCE,
Azure Identity and MSAL tooling.

## Backend And Target Parity

Interpreter, Python compiler, JavaScript compiler, Node, browser and hosted
contracts remain unchanged. The exact-source prelude cache and all prior RC
regressions remain covered. Require supported Python 3.10–3.13/platform CI,
retained conformance, deep differential quality and all six existing latency
budgets. Do not use RC.4's results as qualification for the new build/dependency delta.

## Compatibility And Migration

No Geno source or runtime dependency migration is introduced. Setuptools 84.1.0
supports the project's existing Python 3.10 floor. The build minimum is intentional.
Retain the 0.5-to-0.6 migration guidance, frozen corpora and Preview/Alpha labels.
Fresh public wheel and sdist installations must use their tested artifact hashes.

## Security And Resource Limits

Main's Dependabot alerts 34 and 35 became fixed after #222, not dismissed.
That status does not describe unchanged RC.4 artifacts. Verify actual candidate
locks and installed trees with fresh audits; do not rely on dashboard status alone.

All sandbox, capability, reserved-name and resource-limit policies remain unchanged.
Carry forward only freshly supported residual findings, their exposure and owner.
Preserve the MSAL cross-major compatibility limitation without claiming a live
publishing test that was not performed.
