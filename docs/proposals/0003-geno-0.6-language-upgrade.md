- Status: Draft
- Authors: David Iach (direction), Claude Code (drafting and implementation)
- Created: 2026-10-23
- Discussion: TBD
- Supersedes: None
- Review: None (single-maintainer acceptance under `GOVERNANCE.md`); automated

## Summary

Geno 0.6 is a deliberate, breaking upgrade whose goal is to make Geno a
99th-percentile programming language for its stated purpose: reliable small
and medium programs written by language models and the people who review
them. This proposal defines what "99th percentile" means in measurable terms,
records the four direction decisions the project lead has made, and lays out
the milestones that get there. Each milestone that changes the language gets
its own focused proposal (0004 onward) that this roadmap links to.

The four decisions:

1. **LLM-first, human-excellent.** Geno keeps the features that make it
   distinctive — explicit `end` blocks, executable `example` clauses,
   `requires`/`ensures` contracts, named arguments for calls with three or
   more parameters, effects, and capabilities — and otherwise matches the
   design quality of the best mainstream languages.
2. **One error model: `Result` + `?`, with `panic` for bugs.** `throw`,
   `try`, and `catch` are removed. Bugs abort the program and cannot be
   caught by Geno code; only the host sees them.
3. **Ship as 0.6 with `geno migrate`.** The breaks land in the 0.6 minor
   series under the pre-1.0 compatibility policy, each with an accepted
   proposal, a changelog migration note, and conformance cases. A
   `geno migrate` command mechanically rewrites 0.5 source wherever a
   rewrite is mechanical.
4. **Milestones land in order, one validated change at a time.**

## What "99th Percentile" Means

Among programming languages that have real users, the top one percent —
Rust, Kotlin, Swift, F#, OCaml, Gleam, Elm, TypeScript — differ from the rest
on a short list of properties. Geno adds one more that follows from its
purpose. Each row below is a pass/fail bar for the 0.6 series.

| # | Pillar | 99th-percentile bar | Geno 0.5 |
|---|---|---|---|
| P1 | Abstraction | Users write generic functions and generic types; traits have bounds; the standard library is generic. | No user generic functions. The stdlib's `List.zip`, `Option.map`, `List.find` are `Int`-only. Traits have no bounds or defaults. |
| P2 | Soundness | Every accepted program is well typed with no escape hatch: no wildcard types in accepted programs, one error model, no host-dependent typing. | `TypeVar` and `Any` act as wildcards at call sites. Two error models; the open soundness bugs #193, #196, #197 all come from typed `catch`. |
| P3 | Ergonomics | Low ceremony where it buys nothing: method-call chains, contextual inference for lambda and loop variables, expression-oriented control flow, or-patterns, tuple access. | `xs.map(f)` is a type error. `fn(x) -> ...` and `for x in xs` are parse errors. No `if` expression, no or-patterns, no `t.0`. |
| P4 | Coherent stdlib | One name per operation, generic, discoverable through methods, no duplicates. | 231 flat builtins, with duplicates (`abs`/`math_abs`, `trim`/`string_trim`, three `contains` variants) and filler (`add`, `subtract`, `is_positive`, `square`). |
| P5 | Host hygiene | Source-language names never collide with a backend's host names. | `len`, `map`, `id`, `type`, `str`, `list`, `format`, `print` are rejected as Geno identifiers because they clash with Python. |
| P6 | Runtime robustness | Ordinary recursive programs run under default limits on every lane. | The interpreter lane stops at recursion depth 500, and `fib(24)` exceeds the default 1M step limit. |
| P7 | Diagnostics | Every error has a stable code, a precise span, and, where unambiguous, a suggested fix a tool can apply. | Codes and spans are good. Cascades through `Any` produce follow-on errors such as "Cannot call non-function type: Any". |
| P8 | Tooling | Stable formatter, LSP, test runner, and docs generator. | Formatter and LSP are Experimental. |
| P9 | Specification | Normative spec, machine-readable spec, frozen conformance corpus, compatibility policy. | Strong. Keep it that way: every milestone updates all of them. |
| P10 | LLM reliability | Published, reproducible pass@1 and repair-loop results against Python on the benchmark corpus, for at least three frontier models. | Methodology exists; no published result. |

P9 is already at the bar. Geno's safety features (contracts, examples,
effects, capabilities, typed holes) are ahead of most languages on the list
and stay.

## Design Principles For 0.6

1. **Familiar wherever familiarity is free.** A language model's prior comes
   from Python, TypeScript, Rust, Kotlin, and Swift. Where Geno differs from
   all of them without buying safety, the difference is a defect: it costs
   first-try correctness and teaches nothing. Where Geno differs *to* buy
   safety (`end` blocks, examples, named arguments, capabilities), it keeps
   the difference and explains it in diagnostics.
2. **One obvious way.** Each operation has one name. Each concept has one
   construct. Removing a duplicate is preferred over documenting it.
3. **Sound by construction.** A wildcard type may exist during error
   recovery, but never in a program that type-checks.
4. **Every layer at once.** A language change lands in the lexer, parser,
   AST, typechecker, interpreter, Python and JavaScript backends, formatter,
   LSP where relevant, `docs/spec/v0.6.md`, `spec.json`, the conformance
   corpus, and tests in the same change. Self-hosted frontend parity is
   tracked separately and may lag, as `selfhost/SCOPE.md` already allows.
5. **Mechanical migration.** If a break can be rewritten mechanically,
   `geno migrate` rewrites it. If it cannot, the diagnostic for the old form
   names the new one.

## Milestones

Each milestone ends with green targeted local CI, updated docs and spec, and
conformance cases on every backend. Milestones that change syntax or
semantics get a focused proposal.

| M | Scope | Pillars | Breaking? | Proposal |
|---|---|---|---|---|
| M1 | User-defined generic functions `func f[T, U](...)`, rigid type parameters in bodies, call-site instantiation, explicit type arguments; generic standard-library wrappers | P1, P2 | No (additive); stdlib signatures widen | [0004](0004-generic-functions.md) |
| M2 | Bounds on type parameters: built-in `Num`/`Ord`/`Hash` and trait names | P1, P2 | No | [0005](0005-type-parameter-bounds.md) |
| M3 | Method-call syntax: `x.f(a)` resolves to a field, a trait method, a function, or the receiver type's builtin | P3, P4 | No | [0006](0006-method-call-syntax.md) |
| M4 | Contextual inference for lambda parameters, `for` and comprehension variables, and tuple destructuring | P3 | No | [0007](0007-contextual-type-inference.md) |
| M5 | `if` expressions, or-patterns, tuple fields `t.0`, map literals | P3 | No | [0008](0008-expression-ergonomics.md) |
| M6 | Result-only error model: remove `throw`/`try`/`catch`, add `panic`, total accessors (`get`, `first`) returning `Option` | P2 | **Yes** | 0009 |
| M7 | Coherent stdlib: remove duplicate and filler builtins, method-friendly generic names; `geno migrate` for 0.5 sources | P4 | **Yes** | 0010 |
| M8 | Host-name hygiene (mangle backend identifiers), interpreter recursion depth and step defaults that run ordinary programs | P5, P6 | Relaxes rules | 0011 |
| M9 | Tooling to Stable: formatter idempotence over the whole corpus, LSP coverage of the new forms | P7, P8 | No | — |
| M10 | Publish the LLM correctness benchmark for 0.6 | P10 | No | — |

Additive milestones (M1–M5, M8) come first so that by the time M6 and M7
remove old forms, every removed form already has a better replacement in the
same release.

## Compatibility And Migration

- The 0.6 series gets `docs/spec/v0.6.md` (forked from v0.5 and amended per
  milestone) and `conformance/v0.6`. `docs/spec/v0.5.md` and
  `conformance/v0.5` are retained unchanged, as the compatibility policy
  requires.
- Additive milestones do not change the meaning of any accepted 0.5 program.
- Breaking milestones (M6, M7) each carry before/after examples in
  `CHANGELOG.md` and the compatibility policy's "Recorded Breaking Changes"
  section, and a `geno migrate` rule where the rewrite is mechanical.
- Published diagnostic codes are never repurposed; new rules get new codes.

## Security And Resource Limits

No milestone grants a capability, widens a sandbox, or changes host trust
boundaries. M6's `panic` is a runtime failure with the same reporting path
as an uncaught runtime error today. M8 changes default interpreter limits;
the hosted runtime and sandbox keep their configured limits and fail-closed
behavior, and the change is reviewed against `make security`.

## Testing And Validation

Every milestone adds parser, typechecker, interpreter, Python, JavaScript,
and backend-parity tests, conformance cases under `conformance/v0.6`, and
docs-snippet coverage for new spec examples. Milestones run
`scripts/local_ci.py targeted`; M6, M7, and the 0.6 release run `full` and
`release`.

## Rollout

Milestones land in order on the 0.6 development line. The 0.6.0 release
requires M1–M8. M9 and M10 may follow in 0.6.x without blocking it.

## Alternatives

- **Do nothing / bug-fix only.** Leaves P1–P6 unmet. Generic functions alone
  are table stakes for every language on the comparison list.
- **General-purpose, human-first redesign.** Rejected by the lead: Geno's
  differentiation is reliability of generated code, and the LLM-specific
  rules are the evidence-backed part of that.
- **Typed checked exceptions instead of Result-only.** More familiar to
  models, but keeps two error models and the backend complexity behind
  #193, #196, and #197. Rejected by the lead.
- **Go straight to 1.0.** Freezes the redesign before it has been used.
  Rejected in favor of 0.6.

## Findings During Implementation

- **Local mutation is an effect.** A function that only mutates its own
  `var` locals is typed `with mutation`, so it cannot be passed where a pure
  function type is expected, although callers cannot observe the mutation.
  Masking effects on state that does not escape (as Koka does) belongs with
  declared effects on trait methods in a later effect-system milestone.
- **Imports were transitive in the checker only.** Fixed during M1: 0.5
  accepted programs that then failed with a name error in compiled Python and
  JavaScript.

## Unresolved Questions

- Whether `Array` and `Vec` should merge in M7 (both are mutable sequences).
- Whether `panic` should be catchable at a test boundary (`geno test`
  expecting a panic); current lean: yes, via an `example ... panics` clause
  rather than a language-level catch. M6 shipped without it (proposal 0009).
