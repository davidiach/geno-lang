## 1. Overview

Geno is a programming language designed for LLM code generation. Key principles:
- Explicit block delimiters (`end func`, `end if`) instead of braces
- Explicit function signatures with local type inference
- Specification-first design with `example`, `requires`, `ensures`
- Immutability by default (`let` vs `var`)
- Named parameters required for 3+ argument calls

## 2. Lexical Structure

### 2.1 Whitespace and Comments
- Whitespace (spaces, tabs, newlines) separates tokens
- Single-line comments: `// comment to end of line`
- Block comments: `/* multi-line comment */`

### 2.2 Identifiers
- Variables/functions: `[a-z_][a-zA-Z0-9_]*` (snake_case)
- Types/constructors: `[A-Z][a-zA-Z0-9]*` (PascalCase)

### 2.2.1 Host Names
An identifier means the same thing on every backend, whatever the host
language calls its own builtins. A program may name a function `len`, a local
`list`, a parameter `console` or a constructor `Error`, and may define a
top-level function or constant with a builtin's name, such as `max`, which then
refers to its own definition throughout the program:

```geno
type Fault = Error(msg: String) | Exception(code: Int)

func len(xs: List[Int]) -> Int
    example [1, 2] -> 2
    return length(xs)
end func
```

The Python and JavaScript compilers emit such a name with the suffix `_g`
(`len_g`, `Error_g`), and a target keyword with `_kw`; values still print
and match by their Geno names. Names that begin with `_` and that the runtime
itself uses (`_safe_add`, `_GENO_CAPS`) remain reserved and are rejected. A
program may not spell both a name and its emitted form (`len` and `len_g`).
The names of the isolated `geno run` lane's host channel (section 9.11.1)
are reserved this way on every target, the JavaScript one included.

### 2.3 Literals
- Integers: `-?[0-9]+` (e.g., `42`, `-17`)
- Floats: `-?[0-9]+\.[0-9]+` (e.g., `3.14`, `-0.5`)
- Strings: `"..."` with escapes `\n`, `\t`, `\\`, `\"`
- Multi-line strings: `"""..."""`
- F-strings: `f"text {expr} more text"` with interpolated expressions
- Booleans: `true`, `false`

### 2.4 Keywords
```
and assert async await break catch continue do else end ensures example export
false fn for func if impl import in let match not or ref requires return test
then throw trait true try type var where while with
```

> **Note:** `ref` is a reserved keyword but is not currently implemented.
> `throw`, `try` and `catch` are reserved but no longer form any construct:
> Geno 0.6 removed exceptions (section 6.9), and each is rejected with E205
> naming its replacement.
> `break` and `continue` are supported inside `while` and `for` loops.

### 2.5 Operators
```
+  -  *  /  %           // Arithmetic
**                      // Exponentiation (right-associative)
&  ^  <<  >>  ~         // Bitwise (AND, XOR, left shift, right shift, NOT)
== != < > <= >=         // Comparison
and or not              // Logical
=                       // Assignment
->                      // Arrow (return type, lambda)
|>                      // Pipeline
|                       // Pattern separator
?                       // Propagation (Option/Result)
```

> **Note:** Bitwise OR uses the `bit_or(a, b)` builtin instead of `|` to avoid
> ambiguity with the pattern separator in match expressions.
> Unary `-` binds more tightly than exponentiation in Geno, so `-2 ** 2`
> parses as `(-2) ** 2`.

### 2.6 Delimiters
```
( ) [ ] { } , : ; . _ ?
```

## 3. Types

### 3.1 Primitive Types
```
Int       // Integer
Float     // Floating point
String    // Text
Bool      // Boolean (true/false)
Unit      // Empty tuple ()
```

For code that targets JavaScript, portable `Int` values range from
`-(2^53 - 1)` through `2^53 - 1`. JavaScript target checks and compilation
reject integer literals and integer pattern literals outside that range;
runtime operations reject out-of-range results rather than rounding them.
Interpreter and compiled Python execution instead use the configurable
`max_integer_bits` limit (33,219 bits by default).

### 3.2 Compound Types
```
List[T]           // Homogeneous immutable list
Map[K, V]         // Immutable key-value map
Option[T]         // Some(value) | None
Result[T, E]      // Ok(value) | Err(error)
Async[T]          // Result of an async function (resolved with await)
(T1, T2, ...)     // Tuple types
```

### 3.2.1 Mutable Collection Types
```
Array[T]          // Fixed-size mutable array (reference type)
Vec[T]            // Growable mutable vector (reference type)
Set[T]            // Mutable hash set (reference type)
MutableMap[K, V]  // Mutable hash map (reference type)
```

Mutable collections are reference types: assignments share the underlying data.
Use them for performance-critical or interactive code (e.g., games).

User-defined constructor values have value semantics. Binding an existing
constructor value creates a snapshot, and a `with` expression returns an
independent constructor value. Subsequent field assignment through a `var`
binding does not mutate an earlier snapshot.

### 3.2.2 Built-in ADT Types

These types are pre-defined and available without explicit `type` declarations:

```geno
type JsonValue = JsonString(value: String)
    | JsonInt(value: Int)
    | JsonFloat(value: Float)
    | JsonBool(value: Bool)
    | JsonNull
    | JsonArray(items: List[JsonValue])
    | JsonObject(entries: List[(String, JsonValue)])

type HttpResponse = HttpResponse(status: Int, body: String, headers: List[(String, String)])

type ProcessResult = ProcessResult(exit_code: Int, stdout: String, stderr: String)

type FileKind = FileKindFile
    | FileKindDirectory
    | FileKindSymlink
    | FileKindOther

type FileMetadata = FileMetadata(kind: FileKind, size: Int, modified_ms: Int)
```

### 3.3 Function Types
```
(T1, T2) -> R     // Function taking T1, T2, returning R
(Int) -> Int      // Single parameter
() -> Unit        // No parameters, no return value
```

### 3.4 Generic Types
```
List[Int]
Option[String]
Result[Int, String]
Map[String, Int]
```

### 3.5 Function Effects

Function types carry a set of semantic effects. An effect annotation follows
the return type and uses `with`:

```geno
@untested("host filesystem example")
func read_config(path: String) -> String with fs
    return fs_read_text(path)
end func

type Callback = (String) -> Unit with io
```

The valid effect names in Geno 0.7 are `clock`, `env`, `fs`, `http`, `io`,
`mutation`, `process`, `random`, `regex`, and `stdin`. The 0.5 `throw` effect
is removed (E205); a panic is not an effect.

*Changed in 0.7 (proposal
[0019](../proposals/0019-local-mutation-is-not-an-effect.md), Accepted).* A
function's effects describe what its callers can observe, so changing state
that only the function's own call can see is not an effect. 0.6 charged
`mutation` for every `var` and every assignment.

- Calling an effectful function propagates its effects to the caller.
- A write is a `mutation` unless only the writing function or lambda can
  observe it. Declaring a `var` is never an effect. Assigning a variable is
  an effect only in a lambda that assigns a variable captured from an
  enclosing scope; the lambda carries `mutation`, and the function that
  creates the lambda does not. A field or index write through a
  variable of the writing function or lambda is not an effect when every
  value it steps into has value semantics (constructor values, `List`,
  `Map`, tuples), or when the only reference collection it steps into is the
  variable's own and the variable is *owned*. Every other write is a
  `mutation`: through a parameter's collection or a copy of one, below a
  reference-typed field or element, or through a captured variable.
- A variable is owned when its collection is allocated by the writing
  function or lambda and never escapes. Its name is not a parameter; every
  declaration of the name in the body is a `var` initialized from a call of
  an allocating builtin (`array_new`, `array_from_list`, `array_copy`,
  `vec_new`, `vec_from_list`, `set_new`, `set_from_list`, `set_union`,
  `set_intersection`, `mutable_map_new`), and every assignment to it assigns
  such a call. It is not mentioned in a nested lambda, and each other use is
  the root of an index or field write, an index read, an argument a builtin
  only borrows (in a call, or piped into a builtin's pipeline stage as in
  `counts |> array_to_list`), the container of `in`, the iterable of a
  `for` loop or comprehension, or a returned value (alone, as an element
  of a returned tuple, list or constructor call, or as a branch of a
  returned `if` or `match` expression). The test considers the whole
  body of the function or lambda, by name.
- Writing a reference collection that is reachable from outside the writing
  function or lambda is a `mutation`, whether the write is an index
  assignment or a mutating builtin (`vec_push`, `array_set`, `set_add`,
  `mutable_map_set` and the others). A builtin applied to an owned
  variable is not an effect.
- Capability-gated builtins contribute the corresponding semantic effect.
- When a function has no annotation, its effects are inferred. When an
  annotation is present, every inferred effect must be included in the
  declared set; a declared superset is allowed. A pure function can be used
  where a more-effectful callback is accepted, but not the reverse.

```geno
func histogram(xs: List[Int], buckets: Int) -> List[Int]
    example [0, 1, 1], 3 -> [1, 2, 0]
    var counts = array_new(buckets, 0)    // owned: allocated here, never escapes
    for x in xs do
        counts[x] = counts[x] + 1         // not an effect
    end for
    return array_to_list(counts)
end func

func bump(counter: Array[Int]) -> Int with mutation
    example array_new(1, 0) -> 1
    var alias = counter                   // copies the reference, not the array
    alias[0] = alias[0] + 1               // the caller's array changes
    return alias[0]
end func
```

`histogram` is `(List[Int], Int) -> List[Int]`, a pure function type. `bump`
would infer `mutation` without its annotation.

*Known limitation (0.7 draft).* The reference checker does not yet charge
mutating builtins on any receiver, so `vec_push(v, x)` on a parameter `v`
is not reported as `mutation`. A function that changes its caller's
collection only through such a builtin is therefore inferred pure, even
when it also assigns a local `var` (which 0.6 charged), unless it declares
`with mutation`. A program that relies on this is outside the rule above,
and a future checker may reject it. Passing a `var`-held constructor value
to a function does not snapshot it on any backend, so a closure the callee
builds over that parameter observes later field writes through the `var`
(see 3.2.1). An element or field read passed as an argument (`f(a[0])`,
`f(b.p)`) is not changed by a later field write through the same place, and
a `for` loop over an `Array` iterates a snapshot of its elements, on every
backend. None of these cases lets a masked write reach a caller without an
uncharged builtin store.

Effects are a static type-system property. Capabilities are runtime authority;
declaring `with fs` does not grant the `fs` capability.

## 4. Declarations

### 4.1 Function Definitions
```
func <name>(<params>) -> <return_type>
    <specs>
    <body>
end func [<name>]
```

Example:
```geno
func add(x: Int, y: Int) -> Int
    requires x >= 0
    requires y >= 0
    ensures result >= x
    example 2, 3 -> 5
    example 0, 0 -> 0

    return x + y
end func add
```

The closing `end func` may optionally include the function name for clarity.

### 4.1.1 Entrypoint Results and Imports

**Entrypoint selection.** Only a `main` declared in the selected entry program
is executable entrypoint state. A function named `main` in an imported module is
an ordinary function, and import discovery never changes entrypoint ownership.

An entrypoint's result is classified from its resolved static return
annotation, including aliases imported into the entry program.

**Execution form.** An `async main` is awaited exactly once before its result is
classified. The language also permits `await` directly inside a synchronous
`main`; such an entrypoint is an asynchronous execution form even without the
`async` modifier, and hosts must lower and await it exactly once. A synchronous
`main` that merely *returns* an async value without awaiting it is not
implicitly awaited; it follows the ordinary rule for its declared return type.

**Result normalization at an executable boundary.** In the 0.6 language series:

1. `main() -> Unit` produces status 0.
2. `main() -> Int` produces `result % 256`, in the inclusive range 0 through
   255, and produces no implicit stdout. Modulo is mathematical, so `-1`
   normalizes to 255 and `258` normalizes to 2. Normalization happens once, at
   the host boundary, after the language value has been produced.
3. `main() -> Result[T, E]` (Geno 0.6, [proposal 0009](../proposals/0009-result-only-errors.md)):
   `Ok(v)` is handled as rule 1, 2 or 4 would handle a `main` returning `v`
   of type `T`; `Err(e)` writes `Error: ` followed by the display form of `e`
   (a `String` without quotes) and a newline to standard error, and produces
   status 1. So `?` propagates to the process boundary.
4. Other accepted `main` return types keep their v0.4 surface behavior and
   status 0. The primary CLI and standalone artifacts keep displaying those
   results; the legacy self-hosted command adapter keeps omitting the inner
   result.
5. An entry program with no `main` and no other target-defined lifecycle
   entrypoint is a successful no-op: status 0 and no implicit output. App-mode
   programs (section 9.12) are excluded and keep their own behavior.

A type error or an uncaught runtime error is not a normal result; existing
diagnostics and nonzero failure behavior apply.

**Output and diagnostics.** All output accepted before a normal `main` result is
delivered before the host terminates. A normal nonzero integer result is not
wrapped as a runtime exception and emits no traceback or runtime diagnostic.
Genuine uncaught errors still produce the target's Geno-facing diagnostic and a
nonzero process status.

*New in 0.7 (proposal
[0018](../proposals/0018-runtime-failure-diagnostics.md), Accepted).* That
diagnostic is the runtime report of section 6.9.1 on every executable
boundary: the `geno run` lanes, standalone compiled Python, and Node
CommonJS and ESM entry builds. A standalone artifact prints the report, with
its Geno location and stack, instead of a host traceback, and exits 1 as
before. A Node entry build exits as soon as it has printed the report, for an
async `main` too, so pending asynchronous work never runs after it. A build
owns the process only when it runs as the entry point: a CommonJS build that
a host `require()`s lets a failure of its `main` propagate to the requirer,
as in 0.6, and changes no process-wide setting. The entry path writes stdout
and stderr in blocking mode, as compiled Python and the interpreter do, so
the immediate exit loses none of the output printed before the failure, even
through a full or slow pipe (0.6's synchronous fatal path could). An `Err`
returned from
`main` is a normal result, not a runtime failure: it still writes only
`Error: ` and the value, with no location or stack.

**Embedding and imports.** Embedding APIs and generic sandbox result channels
return the raw Geno value without normalizing it and without terminating their
host: an embedded integer result of 258 is returned as 258, not 2. `geno run
--json` is an executable CLI boundary rather than an embedding API: its envelope
carries the raw, unnormalized value while the command exits with the normalized
status. Importing generated Python or Node ESM does not invoke `main` or exit
the importing process. Browser-targeted ESM has no process boundary and remains
an auto-start artifact that displays an integer result; it reports an `Err`
from `main` on the console's error stream. An embedding API returns a `main`
`Result` as the raw value, `Err` included, and `geno run --json` carries it raw
in `value` while the command exits 1.

This section is the entrypoint contract change from v0.4; sections 4.2, 4.6 and
7.15 carry the other three. See accepted proposal
[0001](../proposals/0001-executable-entrypoint-exit-semantics.md) for this
section's rationale, migration path and full compatibility analysis.

### 4.1.2 Generic Functions

A function may declare type parameters in brackets after its name:

```geno
func first_or[T](xs: List[T], fallback: T) -> T
    example [1, 2], 0 -> 1
    example [], "none" -> "none"
    match xs with
        | [] -> return fallback
        | [x, ...] -> return x
    end match
end func
```

**Declaration rules** (violations report E320):

- Type parameter names are PascalCase and distinct within one function.
- A type parameter may not reuse the name of a built-in type or of a type or
  type alias defined in or imported into the module.
- Every type parameter appears in at least one parameter type or in the return
  type.
- `main`, `init`, `update`, and `render` cannot declare type parameters, and
  neither can a method in an `impl` block.

**Inside the function**, in its parameter and return types, `requires` and
`ensures` clauses, body, local annotations, and lambdas, each type parameter is
an opaque type compatible only with itself. A value of type `T` may be passed
to any parameter that accepts every type, stored in lists, tuples, options,
results, and user-defined types, compared with `==` and `!=` against another
`T`, converted with `to_string`, printed, and interpolated in an f-string. It
is not numeric, not ordered, and not hashable unless a bound (section 4.1.3)
says so: without one, arithmetic, `<`, `<=`, `>`, `>=`, and use as a `Map` or
`MutableMap` key or `Set` element are rejected.

**At each use**, the type parameters are instantiated afresh:

- A call infers them from its arguments, left to right, and from the expected
  type of the call when a parameter appears only in the return type. The result
  type is the return type under that instantiation. Arguments that bind one
  parameter inconsistently are a type mismatch that names the bound type.
- Each `example` clause is a separate instantiation, so one function's examples
  may use different types.
- A generic function used as a value, rather than called, is instantiated by
  the type its context expects: a call parameter, an annotated `let` or `var`,
  a `return`, a list element, or a constructor field. If a type argument is
  still undetermined once the program is checked, the program is rejected
  (E321); an annotation such as `let f: (Int) -> String = show` fixes it.

Generic functions are exported, imported, and called unqualified or qualified
(`Lib.first_or(xs, 0)`) like any other function. Their type parameters are local
to the function and are not part of the module's exported type surface.

Every backend gives each instantiation the same behavior. In particular a
`Float` passed through a type parameter keeps its `Float` formatting
(`to_string(2.0)` is `"2.0"`) on every target.

### 4.1.3 Type Parameter Bounds

A type parameter may declare bounds after a colon, joined with `+`:

```geno
func largest[T: Ord](xs: List[T], fallback: T) -> T
    example [3, 9, 2], 0 -> 9
    var best = fallback
    for x: T in xs do
        if x > best then
            best = x
        end if
    end for
    return best
end func
```

A bound is `Num`, `Ord`, `Hash`, or the name of a trait in scope; any other
name is rejected (E322). `Num` implies `Ord`, and `Ord` implies `Hash`.

| Bound | Satisfied by | Permits inside the function |
|---|---|---|
| `Num` | `Int`, `Float` | arithmetic, negation, ordering, hashing |
| `Ord` | `Int`, `Float`, `String` | `<`, `<=`, `>`, `>=`, hashing |
| `Hash` | any type allowed as a `Map` key or `Set` element | use as a `Map` or `MutableMap` key or `Set` element |
| trait `Tr` | a user-defined type with an `impl Tr` | calling `Tr`'s methods with the value as receiver |

A type parameter satisfies the bounds it declares and those they imply, so one
generic function can pass its values to another that requires the same bound.
Each instantiation (a call, an example clause, a function value) must satisfy
every bound of every type parameter; a type argument that does not is
rejected at that use (E323).

For `T: Num`, the operators `+`, `-`, `*`, `/` and `%` give `T` when both
operands are `T`, or one is `T` and the other `Int`, and give `Float` when one
operand is `T` and the other `Float`. Division of a `T` that is `Int` truncates
toward zero, as for any `Int`. Two different numeric type parameters cannot be
combined. Integer literals are not values of type `T`.

A call to a trait method whose receiver has type `T: Tr` dispatches on the
value at run time. Its effects are those of every implementation of the
method in the program.

### 4.1.4 Self Tail Calls

*Unreleased (proposal [0022](../proposals/0022-self-tail-calls.md), Accepted).* A function's
call to itself in tail position replaces the running call instead of nesting
inside it, so a tail-recursive function is as deep as a loop is long:

```geno
func sum_to(n: Int, acc: Int = 0) -> Int
    example (3) -> 6
    if n == 0 then
        return acc
    end if
    return sum_to(n - 1, acc + n)
end func
```

A call is a **self tail call** when all of these hold:

1. It is in a top-level function that is not `async`. Methods of an `impl`
   and lambdas have none.
2. Its callee is the function's own name, written as a plain name, and the
   function binds that name nowhere (no parameter, `let`, `var`, loop
   variable, pattern variable or lambda parameter of that name).
3. It is in tail position:
   - the whole value of a `return` statement, at any nesting inside `if`,
     `match`, `for` and `while` statements;
   - the value of a branch of an `if` expression or of an arm of a `match`
     expression that is itself in tail position;
   - in a function that returns `Unit`, the last statement of the body, or
     the last statement of a branch of an `if` statement or an arm of a
     `match` statement that is itself the last statement.
4. It is not inside a lambda.

Every other call is an ordinary call and nests: mutual recursion, a call
through a function value or a module-qualified name, a pipeline stage,
`f(x)?`, and any call whose result is used, such as `1 + f(n - 1)`.

A self tail call behaves as the call it replaces in every way but depth:

- Arguments are evaluated in the order written, and all of them before any
  parameter takes its new value. Defaults are evaluated for each logical call
  that omits the argument.
- `requires` is checked on each logical call's arguments.
- `ensures` holds for each logical call. Every call a tail call replaced
  returns the final result, so once it is known each call's clause is checked
  with that call's own parameters, innermost first.
- A closure keeps the bindings of the logical call that created it.
- The step limit and the timeout apply as before. A self tail call does not
  count toward the recursion depth limit, so a tail recursion that never ends
  is stopped as a loop that never ends is, by the step limit or the timeout
  ([compatibility policy](../operations/compatibility-policy.md#07-draft-a-self-tail-call-does-not-nest)).
- A runtime failure report (section 6.9.1) shows one frame for the function,
  whatever number of calls a tail call replaced, and no count of them.

Every backend runs the same calls this way, so a program is as deep on one as
on another.

### 4.2 Type Definitions
```
type <Name>[<type_params>] = <variants>
```

Variants may be separated across lines, and an optional leading `|` may
precede the first variant:
```geno
type Tx =
    | Deposit(amount: Int)
    | Withdraw(amount: Int)
```

Examples:
```geno
// Simple enum
type Color = Red | Green | Blue

// Generic type with fields
type Maybe[T] = Just(value: T) | Nothing

// Recursive type
type Stack[T] = Push(top: T, rest: Stack[T]) | Empty

// Record-like type
type Point = Point(x: Int, y: Int)
```

A type or type alias name may be defined once per module and may not reuse a
built-in type name (`Int`, `Float`, `Bool`, `String`, `Unit`, `List`, `Array`,
`Map`, `MutableMap`, `Vec`, `Set`, `Tuple`, `Async`, `Option`, `Result`,
`JsonValue`, `HttpRequest`, `HttpResponse`, `ProcessResult`, `FileKind`,
`FileMetadata`). The constructors of one type must have distinct names.
Different types in the same unqualified type scope must also have distinct
constructor names, including types exposed by unaliased imports. Both project
checking and the embedding API report E309 at the conflicting type declaration.

Target-aware checks reject record field names that the selected backend cannot
represent safely. Python targets reject Python keywords and dunder fields.
JavaScript targets reject JavaScript keywords, `_tag`, `_withGenoFormatter`,
`__proto__`, `constructor`, and `prototype`. Without a declared target,
`geno check`, `geno test`, and editor diagnostics validate Python lowering when
the selected entrypoint module defines `main`, matching the default `geno run`.
Libraries whose entrypoint has no `main` remain permissive; a `main` in an
imported module does not change their role. Targetless embedding API
`geno.check()` remains an interpreter-oriented language check and makes no
backend-lowering guarantee unless a target is explicitly selected.

### 4.3 Parameters

Parameters require explicit type annotations:
```geno
func greet(name: String, times: Int) -> String
```

All parameters are passed by value. Geno emphasizes immutability, so there are
no reference parameters.

### 4.3.1 Default Parameter Values

Parameters may have default values. Required parameters must precede optional ones:
```geno
func connect(host: String, port: Int = 8080, timeout: Int = 30) -> String
    example "localhost" -> "localhost:8080"
    return host + ":" + to_string(port)
end func
```

Callers may omit trailing optional arguments or override them positionally or
by name:
```geno
connect("localhost")                          // port=8080, timeout=30
connect("localhost", 3000)                    // port=3000, timeout=30
connect(host: "localhost", timeout: 60)       // port=8080, timeout=60
```

### 4.3.2 Async Functions

Prefixing a function with `async` makes it return `Async[T]`:
```geno
async func fetch(url: String) -> String
    return "data"
end func
```

- The return type annotation is the inner type `T`, not `Async[T]`
- The actual return type is `Async[T]`; use `await` to resolve it
- Async functions are exempt from `example` clause requirements
- `await` is valid inside `async func` and inside `main()`

### 4.4 Type Aliases

Type aliases create a new name for an existing type:
```geno
type Coordinate = (Int, Int)
type Predicate = (Int) -> Bool
type StringList = List[String]
```

Generic type aliases are supported:
```geno
type Pair[T] = (T, T)
type Mapping[K, V] = Map[K, V]
```

### 4.5 Trait Definitions

Traits define a set of method signatures that types can implement:
```geno
trait Describable
    func describe(self: Self) -> String
end trait
```

The `Self` type in the first parameter refers to the implementing type.
Traits can declare multiple methods.

*Unreleased (proposal 0026):* a trait method's first parameter may be written
`self` alone, meaning `self: Self`; in an impl block (section 4.6) it means
`self` of the implementing type:
```geno
trait Describable
    func describe(self) -> String
end trait
```

### 4.6 Impl Blocks

Impl blocks provide concrete method implementations for a trait on a specific
type:
```geno
type Circle = Circle(radius: Float)
type Square = Square(side: Float)

impl Describable for Circle
    func describe(self: Circle) -> String
        example Circle(1.0) -> "Circle"
        return "Circle"
    end func
end impl

impl Describable for Square
    func describe(self: Square) -> String
        example Square(1.0) -> "Square"
        return "Square"
    end func
end impl
```

Trait methods are called like regular functions with the value as the first
argument:
```geno
let c: Circle = Circle(3.14)
let desc: String = describe(c)    // "Circle"
```

Dispatch works with multi-constructor ADTs:
```geno
type Shape = Circle(r: Float) | Square(s: Float)

impl Describable for Shape
    func describe(self: Shape) -> String
        example Circle(1.0) -> "circle"
        match self with
            | Circle(r) -> return "circle"
            | Square(s) -> return "square"
        end match
    end func
end impl
```

Duplicate impl blocks for the same trait-type pair are rejected at type-check
time. Within one impl block each method name may be defined once; a second
definition of the same name is rejected at that definition rather than silently
replacing the first.

### 4.7 Module Constants

A module-level `let` binds a compile-time constant that every definition in the
same module can read:
```geno
let usage: String = "usage: prog [options]"
let numerals = ["M", "D", "C"]

func help_text() -> String
    example () -> "usage: prog [options]"
    return usage
end func
```

Rules:
- The initializer must be a literal: an `Int`, `Float`, `String`, or `Bool`
  literal, a negated numeric literal, or a list or tuple whose elements are
  themselves literals. A call, an operator expression, a reference to another
  binding, or any other computed form is rejected at parse time.
- The type annotation is optional when the literal determines the type. An
  `Int` literal bound to a declared `Float` is promoted, as in a local `let`.
- Constants are immutable; `var` is not allowed at module level.
- Names are `snake_case`. A leading-uppercase name is a type identifier and is
  rejected.
- Tuple destructuring is not available; bind each name with its own `let`.
- Constants are module-private. They cannot be exported and are not visible to
  importing modules, which must call an exported function instead.
- A constant name may not collide with a function, another constant, or a
  trait method dispatcher in the same module. It may shadow a builtin or a
  host name (see Host Names).
- Backend validation also rejects distinct names that compile to the same
  identifier as a constant. For example, `class` and `class_kw` both become
  `class_kw` in Python and JavaScript. This includes imported functions and
  local bindings; a local with the same source name may still shadow a constant.

## 5. Specifications

### 5.1 Requires Clauses
Preconditions that must be true when function is called:
```geno
requires x > 0
requires length(xs) > 0
requires a != b
```

The `requires` clauses state the function's domain: a property check
(section 5.4) discards a generated input that they reject instead of calling
the function on it.

A clause should be total. A `?` inside a `requires` or `ensures` clause that
propagates `None` or `Err` does not return from the function: the call fails
with a contract violation whose message ends in `('?' propagated None/Err)`,
on every backend.

*New in 0.7 (proposal
[0018](../proposals/0018-runtime-failure-diagnostics.md), Accepted).* A failed
`requires` names the function, the call's argument values and the clause as
written, and is located at the clause's condition; the caller's frame is
positioned at the call (section 6.9.1):

```text
Precondition failed: safe_div(a: 8, b: 0) requires b != 0
Precondition failed: lookup(key: "id") requires parse_int(key)? > 0 ('?' propagated None/Err)
```

### 5.2 Ensures Clauses
Postconditions that must be true when function returns:
```geno
ensures result >= 0
ensures result == x + y
ensures length(result) <= length(input)
```

The special identifier `result` refers to the return value. An `ensures`
clause is a statement about every call in the function's domain, which a
property check (section 5.4) tests on generated inputs.

*New in 0.7 (proposal
[0018](../proposals/0018-runtime-failure-diagnostics.md), Accepted).* A failed
`ensures` also names the function, the call's arguments and the clause, and
adds the result:
`Postcondition failed: shout(s: "hi") ensures length(result) > 10 (result was "hi!")`.
The arguments shown are always the call's; section 6.9.1 says what is added
when the body rebound a parameter the clause reads.

### 5.3 Example Clauses
Concrete input-output pairs (required for non-main functions):
```geno
example 5 -> 120              // Single argument
example 2, 3 -> 5             // Multiple arguments
example [1, 2, 3] -> 6        // List argument
example "hello" -> 5          // String argument
example () -> "usage: prog"   // Zero-argument function
example -> "usage: prog"      // Zero-argument function (equivalent)
```

#### 5.3.1 Panic Examples

*New in 0.7 (proposal
[0017](../proposals/0017-panic-examples-and-property-checks.md), Accepted).* An
example may state that calling the function with its inputs ends in a panic
(section 6.9) instead of returning a value:

```geno
func safe_div(a: Int, b: Int) -> Int
    example 6, 3 -> 2
    example 1, 0 panics "division"     // the panic message contains "division"
    return a / b
end func

func usage() -> String
    example () panics                  // zero-argument function
    panic("not implemented")
end func
```

- **Form.** `example <inputs> panics`, optionally followed by a message
  string: `example <inputs> panics "substring"`. There is no arrow. A
  zero-argument function writes `example () panics`; the bare-arrow form
  `example -> v` has no panics counterpart.
- **`panics` is contextual.** It means "expects a panic" only directly after an
  example's inputs, with no `->`, on the same line as the last input token.
  Everywhere else it is an ordinary identifier: a program may name a variable,
  parameter or function `panics`, and `example panics -> 1` and
  `example x -> panics` keep their 0.6 meaning. It is not a keyword (section
  2.4).
- **Same line.** The message, when present, is a string literal on the same
  line as `panics`; a triple-quoted string is accepted, an f-string is not.
  Any other token after `panics` or its message on that line is an error
  (E201). A string on the next line is the function's first statement, not a
  message.
- **Type checking.** The inputs are checked exactly as for any example (arity,
  defaults, generic instantiation); there is no expected value to check. A
  type parameter that only the return type mentions stays unbound and is not
  bound-checked. A function whose examples are all panics examples satisfies
  the rule that every function has an example.
- **Passing.** The example passes when the call ends in a panic: a call of
  `panic(...)`, or any other runtime error, including a failed `requires` or
  `ensures` at any depth. With a message, the panic's message must also
  contain it, compared ignoring case (Unicode case folding). The inputs are
  evaluated first; an input expression that itself panics is a broken
  example, not a satisfied one.
- **Not a panic.** These never satisfy a panics example, and the failure names
  them:
  - exhausting a resource limit: the step limit, the timeout, the recursion
    depth, host memory or recursion, the collection-size limit, the
    integer-size limit (including the `**`, `<<` and `>>` pre-checks), a
    `Float` power outside the host's range, and the output limit. An example
    must not pass because of the host's limits, and `example 0 panics` must
    not hide an infinite loop;
  - **an explicit exception for host refusals:** a capability denial (E412),
    a missing host callback (E413) and a sandbox security violation (E500).
    Whether they occur depends on what the host grants, not on the input; in
    `geno test` every `env` read is denied, so a function that reads the
    environment would otherwise pass its panics example vacuously. (Proposal
    0017 lists this exception as an open question for the project lead.)
- **Fixed builtin caps are panics.** Argument limits that are part of a
  builtin's documented domain and do not depend on the host's configuration
  are ordinary runtime errors and do satisfy a panics example: `parse_int` and
  `parse_float` input longer than 1000 characters, regex pattern length, text
  length and group nesting depth, `json_parse` nesting depth, and values
  outside the JavaScript-safe integer range where a builtin requires one.
- **Where examples run.** `geno run` (every lane), `geno test`, the embedding
  API with `check_examples` and the hosted server check panics examples with
  the other examples. In `geno run` a panics example whose call returns, or
  panics with another message, fails with E409; one that hits a limit or a
  refusal reports that error with its own code (E501-E503, E499, E412).
  Examples, panics examples included, run with the run's exact capability
  grant in every `geno run` lane. In the default process-isolated lane that
  is the `--cap` list, or `clock`, `print` and `random` without one, with the
  same host restrictions, deadline and output budget as `main` (section
  9.11.1): `--cap regex` denies `print` in examples too, and an example's
  denial is reported before `main` runs. Compiled
  Python and JavaScript do not evaluate examples; compiled Python renders a
  panics example in the function's docstring as `Example: <inputs> panics
  "<message>"`.
- **No arrow.** A panic is not a value an example can expect, so writing one
  after `->` is an error (E330), reported at the arrow before the expected
  value is checked. Each spelling has a fix (section 10.4) that writes the
  `panics` form:

  | Written | Reported when | Rewritten to |
  | --- | --- | --- |
  | `example 1, 0 -> panics` | no `panics` is in scope (a program's own `panics` value keeps the 0.6 meaning) | `example 1, 0 panics` |
  | `example 1, 0 -> panics "division"` | always: a value example has no message | `example 1, 0 panics "division"` |
  | `example 1, 0 -> panic` | `panic` is the builtin | `example 1, 0 panics` |
  | `example 1, 0 -> panic("division")` | `panic` is the builtin | `example 1, 0 panics "division"` |
  | `example 1, 0 -> panic(reason)` | `panic` is the builtin | no fix: the message is not a string literal |
  | `example -> panic("x")` | as above | `example () panics "x"` |

  Two parse errors have fixes too: `example panics` (with or without a
  message) is E201 and gets the missing `()`, and an empty message,
  `panics ""`, is E202 (it matches every panic), with a fix that deletes it.
  **Breaking change from 0.6:** `-> panic("m")` and `-> panic(e)` type-checked
  in 0.6 (`panic` returns `Never`, which every type accepts) and compiled,
  although the example could never pass, because its expected value panics
  before the call is made. Such a program no longer checks;
  `geno check --fix` migrates it:

  ```geno
  // 0.6: accepted, and the example always failed
  example 1, 0 -> panic("division")
  // 0.7 draft
  example 1, 0 panics "division"
  ```

Panic messages are not a stable contract across backends or releases (the
interpreter says `Division by zero: cannot compute 1 / 0`, compiled code
`Division by zero`), so a message should be the part every backend shares or
the text of the function's own `panic`. A panics example also tells a
property check (section 5.4) that the function panics on purpose.

### 5.4 Property Checks

*New in 0.7 (proposal
[0017](../proposals/0017-panic-examples-and-property-checks.md), Accepted).
`geno test --properties` is Experimental
([maturity matrix](../MATURITY.md)); it adds no syntax.* Examples check a
function's contracts on the inputs their author wrote. A property check tests
them on generated inputs: it calls each eligible function on generated
arguments, judges every call against the function's own `requires`, `ensures`
and panics examples, and shrinks a failing input to a small counterexample
that can be pasted after `example`. Given

```geno
func abs_val(n: Int) -> Int
    ensures result >= 0
    example 3 -> 3
    if n >= 0 then
        return n
    end if
    return n
end func
```

plain `geno test` passes (the one example holds), and the property check
reports the bug:

```text
$ geno test --properties abs.geno
  PASS  abs.geno (1/1) 15ms

Properties (seed 0, 100 trials per function)
  FAIL  abs_val  abs.geno:1
        ensures result >= 0 failed (result was -1)
        counterexample: -1
        reproduce: geno test --properties --seed 0 --filter abs_val abs.geno

1 passed, 0 failed, in 0.04s
Properties: 0 passed, 1 failed
```

- **Command.** `geno test --properties [--trials N] [--seed S] PATH`, with
  the other `geno test` options (`--filter`, `--json`, `--timeout`,
  `--max-steps`, `-v`, `--watch`). `--trials` is 1 to 10,000 (default 100);
  `--seed` is a non-negative integer (default 0). Either one without
  `--properties` is a usage error (exit status 2). Without `--properties`,
  `geno test` prints, reports in JSON and exits exactly as in 0.6. Property
  checks run after a file's examples and test blocks, and work on a file, a
  directory and a project.
- **What the contracts mean.** Each call is judged by its outcome:

  | Outcome of the call | Result |
  | --- | --- |
  | It returns, and every `ensures` holds | pass |
  | A `requires` of the function under test evaluates to `false` | **discarded**: the input is outside the function's domain, and another is generated |
  | An `ensures` of the function under test fails | **failure** (`ensures`) |
  | A resource limit (section 5.3.1) | **failure** (`limit`): `requires` is how a function says an input is too large |
  | Any other panic | **failure** (`panic`), unless the function has a panics example, which says it panics on purpose; an `ensures` failure still fails such a function |
  | A host refusal (E412, E413, E500) | the function is **skipped**: its inferred effects missed a capability |

  Only the clauses of the function under test decide a discard or an
  `ensures` failure. A contract that fails in a function it calls is a panic
  of the function under test. A `requires` that cannot be evaluated (it
  panics, or propagates `None` or `Err` with `?`) is a failure, not a
  discard: a precondition should be total.
- **Eligibility.** A function is checked when it is a top-level function or
  an impl method of the file under test or of the project's own modules
  (standard-library and dependency modules are not checked); it is not
  `main`, `init`, `update`, `render`, `async` or `@untested`; its inferred
  effects (section 3.5) are at most `mutation`; and it has at least one
  parameter. Type parameters are instantiated with `Int`. An eligible
  function is reported as skipped, with the reason, when a parameter type has
  no generator or a type parameter's bounds are not met by `Int`. `--filter`
  selects functions as it selects examples; an impl method is named
  `Target.Trait.method`.
- **Generated inputs.** Each argument is generated from its parameter type:

  | Type | Generated values |
  | --- | --- |
  | `Int` | biased to `0`, `1` and `-1`; otherwise at most 2048 in magnitude, and `2^53 - 1` and `-(2^53 - 1)` at 1% each, so always within the portable range (section 3.1) |
  | `Float` | finite only, biased to `0.0`, `-0.0`, `1.0`, `-1.0` and `0.5`, with at most 6 decimal places |
  | `Bool`, `Unit` | every value |
  | `String` | ASCII, at most 16 characters: letters, digits, spaces, tabs, newlines and other printable characters including `"` and `\`, biased to `""`, `" "`, `"0"` and `"a b"` |
  | tuples, `List`, `Option`, `Result`, `Map`, `Set`, `Vec`, `Array` | from their element types, with at most 8 elements; `Map` keys and `Set` elements are distinct; a collection whose element type has no value is generated empty, an `Option` as `None`, and a `Result` from its side that has one |
  | type aliases | as the aliased type |
  | user ADTs, including generic and recursive ones | any variant for up to 5 levels of nesting, then only the variants that need the fewest nested constructors, so generation always ends; an empty collection, `None` and either side of a `Result` end a recursion, so a type recursive only through them (`type Rose = Rose(value: Int, children: List[Rose])`) is generated |
  | function types, `Async`, `MutableMap`, and a type parameter whose bounds `Int` does not meet | none: the function is skipped, also when such a type is part of a parameter type, or of every variant of an ADT the parameter needs (the note names it) |

  Inputs grow over a run: trial `i` of `T` has size `round(64 * i / (T - 1))`,
  from the smallest values to the bounds above. An input is generated as Geno
  source and evaluated in the function's module, as an example's inputs are,
  so the counterexample a report prints is exactly what ran, and every call
  receives fresh values.
- **Determinism.** The default seed is 0, so a run is reproducible and CI is
  deterministic. Each function draws its inputs from its own stream, keyed by
  the seed, its logical module name (the project module, or the file's stem)
  and its qualified name, never by a path: the same seed generates the same
  inputs from any directory or path spelling, and `--filter`, or adding a
  function, never changes another function's inputs. A failure's reproduce
  line repeats the seed, and also `--trials`, `--timeout` and `--max-steps`
  when they are not the defaults.
- **Budgets.** Work is counted in interpreter steps, which are deterministic;
  wall time is only a safety stop:

  | Budget | Limit |
  | --- | --- |
  | One call | 200,000 steps (or `--max-steps`, if smaller), and a wall-clock deadline of `--timeout` (at most 5 s), which is a safety stop |
  | A function's trials | 5,000,000 steps, and at most 10 × `--trials` generated inputs |
  | Shrinking a function's failure | a separate 4,000,000 steps, and at most 500 calls |
  | Safety stop | 2 × `--timeout` of wall time per function, both phases together |

  Generated inputs are small, so a call that needs more than its allowance is
  doing unbounded work, or far more work than a small input should need. How
  a cut-off call counts:
  - A call that started with its full allowance and used it up, or reached
    the recursion depth or a size limit, is a **`limit` failure**, on any
    trial: a loop first reached on the 37th input is a failure, not a
    warning. The report names the per-call allowance: "hit the step limit
    (200,000 steps per property call)".
  - A call that started with less than its full allowance, because the
    phase's budget was nearly spent, and ran out is not counted. In the trial
    phase the function is **`incomplete`** ("stopped after N trials: step
    budget spent") when no failure was found. In the shrink phase, shrinking
    stops and the smallest failing input so far is reported, with a note.
  - A safety stop makes the function `incomplete`, or ends shrinking, with
    a note that says which one fired: the function's, or a call's deadline
    (a call that runs that long without using its step allowance, such as
    one dominated by builtin work the step counter does not see). A call
    never runs past what is left of the function's safety stop. Safety
    stops are the only outcomes that depend on the speed of the machine;
    they are never failures, and the step budgets are set so that they are
    not expected to bind (a call's allowance is about 0.15 s of work).
- **Shrinking.** A failing input is shrunk greedily: candidates are tried in
  order, and the first that fails the same way (the same kind; for `ensures`,
  the same clause; for `limit`, any limit) replaces the input, until no
  candidate fails or the shrink budget is spent. Integers move toward 0 (the
  smallest candidates first, so when every input from some size up fails, the
  first failing candidate is less than twice that size), floats toward 0.0 and
  fewer decimals, strings and collections get shorter and their elements
  smaller, `Option` becomes `None`, and an ADT value becomes a minimal variant
  or one of its own recursive fields. A candidate that the `requires` clauses
  reject is not a failure.
- **Results.** Each checked function has one status: `passed`, `failed`,
  `gave_up` (an input the `requires` clauses accept was found for fewer than
  a tenth of the `T` trials, rounded down, or for none at all, and none
  failed), `incomplete` or `skipped`. Only
  `failed` changes the exit status (to 1); the other three are warnings.
  Property results are not counted in the example totals. The text report is
  always printed with `--properties`; `-v` adds the passed functions (with
  the trials run and discarded) and the skipped ones (with the reason).
- **JSON.** `--json` adds a top-level `properties` object only when
  `--properties` is given, including in the error envelope. Every key is
  always present, `null` when it does not apply:

  ```json
  "properties": {
    "seed": 0,
    "trials": 100,
    "passed": 0, "failed": 1, "gave_up": 0, "incomplete": 0, "skipped": 0,
    "functions": [
      {
        "path": "abs.geno",
        "function": "abs_val",
        "line": 1,
        "status": "failed",
        "trials_run": 3,
        "discarded": 0,
        "failure": {
          "kind": "ensures",
          "message": "Postcondition failed: abs_val(n: -1) ensures result >= 0 (result was -1)",
          "clause": "result >= 0",
          "result": "-1",
          "limit": null
        },
        "counterexample": {"arguments": "-1", "original": "-1", "shrink_steps": 0},
        "note": null
      }
    ]
  }
  ```

  `failure.kind` is `ensures`, `panic` or `limit`; `clause` is the failed
  `ensures` clause's source text, `result` the returned value as the
  interpreter displays it, and `limit` the limit's name (`step limit`,
  `recursion depth limit`, `collection size limit`, ...; never a wall-clock
  deadline, which is a safety stop). `counterexample.arguments` is
  the shrunk input written as an example's inputs, and `original` the input
  first found. The message is the runtime's, which is not a stable contract;
  the reproduce line is in the text report only.
- **Isolation.** Property checks run in the interpreter, in an interpreter of
  their own with no capabilities at all, so a generated input cannot reach
  the filesystem, network, environment, processes, clock or randomness even
  if effect inference missed a gated builtin, and property work never spends
  the step or output budget that examples and test blocks run on. The random
  stream is the host's: Geno code cannot read it or the seed. A
  counterexample is a valid input on every backend, since integers stay
  within the portable range and floats are finite.
- **Contract failure fields.** A failed `requires` or `ensures` raises
  `geno.values.ContractViolationError` (still reported as E499), which
  carries `clause` (`"requires"` or `"ensures"`), `reason` (`"false"` when
  the clause evaluated to `false`, `"propagate"` when it propagated `None` or
  `Err` with `?`), `clause_index` (the clause's position among the function's
  `requires` or `ensures` clauses), `call_depth` (1 for the call a tool made
  with an empty call stack) and, for `ensures`, `result_display` (the
  returned value as displayed). Property checks, `geno test` and example
  verification classify contract failures by these fields, never by message
  text. Later 0.7 changes to contract messages keep them.

  *New in 0.7 (proposal
  [0018](../proposals/0018-runtime-failure-diagnostics.md), Accepted).* The
  exception also carries `function` (the frame display name of section
  6.9.1),
  `clause_text` (the clause as written), `arguments` (the call's
  `(name, value)` pairs, rendered and bounded as section 6.9.1 says) and
  `checked_values` (empty unless an `ensures` saw a rebound parameter).
  Compiled Python's contract exception carries the same fields, with
  `call_depth` `None`; compiled JavaScript's carries `clause`, `reason`,
  `clauseIndex`, `function`, `clauseText`, `arguments`, `resultDisplay` and
  `checkedValues`. In `geno run --json`, the embedding API and the hosted
  server, the JSON diagnostic of a contract failure gains a `contract` object
  beside the `stack` and `stack_omitted` keys every runtime failure gains
  (section 6.9.1). Its code stays E499:

  ```json
  "contract": {
    "clause": "requires",
    "reason": "false",
    "clause_index": 0,
    "function": "safe_div",
    "clause_text": "b != 0",
    "arguments": [{"name": "a", "value": "8"}, {"name": "b", "value": "0"}],
    "result": null
  }
  ```

  `result` is `null` for `requires`. `checked_values`, in the shape of
  `arguments`, appears only when an `ensures` failure saw a parameter rebound
  to a different value.

### 5.5 Testing on the Compiled Backends

*Unreleased (proposal [0024](../proposals/0024-test-backends.md), Draft).
`geno test --backend` is Experimental
([maturity matrix](../MATURITY.md)); it adds no syntax.* `geno test` runs a
program's examples and `test` blocks on the interpreter. `--backend` chooses
where they run:

| `--backend` | Runs the examples and test blocks |
|---|---|
| `interpreter` (default) | on the interpreter, as before |
| `python` | in compiled Python |
| `js` | in compiled JavaScript, on Node |
| `all` | on all three, and compares the outcomes |

- **What runs.** The same cases on every backend: every example, panics
  examples included, of every function and `impl` method, and every `test`
  block; for a project, every module's. `--filter` selects by the same names.
  `main` is not called.
- **How.** The file or project is compiled as `geno compile` compiles it,
  with each example and test block registered as a callable case. The cases
  run in a subprocess. An ordinary build carries none of this.
- **Outcomes.** An example passes when its result equals its expectation
  under Geno equality, with the tolerance `geno test` gives a Float (relative
  `1e-9`). A panics example is decided as section 5.3 says: only a panic in
  the call satisfies it. A failure is reported in
  the interpreter runner's terms: `expected X, got Y`, `Runtime error: ...`,
  and `requires` or `ensures` for a failed contract. A compiled failure
  carries no location or stack.
- **Limits.** The subprocess is granted the capabilities `geno test` grants
  and no others. Each case has `--timeout` seconds; one that runs past it is
  stopped and reported as timed out, and the remaining cases still run.
  `--max-steps` counts interpreter steps and does not apply to compiled code.
- **Divergences.** With `all`, a case diverges when it passes on one backend
  and fails on another, or fails on every backend by returning a different
  value on each. Failures whose runtime errors are worded differently are the
  same outcome. A divergence fails the run.
- **Requirements and combinations.** `js` needs `node`; without it the run
  fails with a message that says so. `--properties` (section 5.4) runs on the
  interpreter only, and combining it with another backend is an error.
- **JSON.** A plain run's `--json` payload is unchanged. With `python` or
  `js` it gains `backend`, on the payload and on each file. `--backend all`
  prints `backends` (each backend's payload, with its `backend` keys),
  `divergences` (each with `path`, `kind`, `function`, `ordinal` and the
  per-backend `outcomes`), the summed counts and `success`.

## 6. Statements

### 6.1 Let Binding (Immutable)
```geno
let x: Int = 5
let name: String = "Alice"
let items: List[Int] = [1, 2, 3]
```

### 6.1.1 Tuple Destructuring

Tuples can be destructured in `let` and `var` bindings:
```geno
let (x, y): (Int, Int) = get_position()
var (a, b): (String, Int) = ("hello", 42)
let (name, count) = ("apples", 3)
```

The annotation may be omitted when the value has a tuple type with determined
element types; the names then take those types in order.

### 6.2 Var Binding (Mutable)
```geno
var count: Int = 0
var buffer: String = ""
count = count + 1    // Assignment allowed
```

Declaring a `var` is not an effect (section 3.5; changed in 0.7 by proposal
[0019](../proposals/0019-local-mutation-is-not-an-effect.md), Accepted): a
function whose only mutation is of its own `var`s is pure.

### 6.3 Assignment
Variable reassignment (for `var` bindings):
```geno
x = x + 1
```

Index assignment on mutable collections (`Array`, `Vec`, `MutableMap`):
```geno
var arr: Array[Int] = array_new(3, 0)
arr[0] = 42
arr[1] = 99

var m: MutableMap[String, Int] = mutable_map_new()
m["key"] = 10
```

Field assignment on constructor values:
```geno
var p: Point = Point(x: 0, y: 0)
p.x = 10
p.y = 20
```

Assigning a local `var`, writing a field of the value it holds, and writing an
element of a collection it owns are not effects; writing into a collection
that a parameter, a captured variable or other storage can reach is a
`mutation` (section 3.5; changed in 0.7 by proposal
[0019](../proposals/0019-local-mutation-is-not-an-effect.md), Accepted). Above,
`arr` and `m` are owned, so none of the writes is an effect.

#### 6.3.1 Compound Assignment

*Unreleased (proposal 0026).* `target op= value` is the assignment
`target = target op value` for `op` one of `+`, `-`, `*`, `/` and `%`, written
with no space between the operator and `=`:
```geno
var total = 0
for x in [1, 2, 3] do
    total += x
end for
p.x -= 1
arr[i] *= 2
```

It is a statement, and its target is a variable, field or index as for `=`.
The target is read and then written, so it may contain names, literals,
field and index accesses and operators, but not a call. The same typing rules
apply as for the assignment written out: the target must be assignable, and
`+=` concatenates strings and lists as `+` does. A `MutableMap` entry and a
`Vec` element are not read with `[...]`, so a compound assignment to one is
rejected.

### 6.4 If Statement
```geno
if <condition> then
    <then_body>
else
    <else_body>
end if
```

The `else` clause is optional:
```geno
if x > 0 then
    print("positive")
end if
```

Chained conditions with `else if`:
```geno
if x > 10 then
    return "large"
else if x > 0 then
    return "positive"
else
    return "non-positive"
end if
```

#### 6.4.1 If Let

*Unreleased (proposal [0023](../proposals/0023-format-specs-slices-named-patterns-if-let.md), Accepted).* `if let` runs its then
branch when a value matches a pattern, with the pattern's variables bound in
that branch only:

```geno
if let Some(user) = find_user(id) then
    print(user.name)
else
    print("no such user")
end if
```

It is the match `match value with | PATTERN -> then-branch | _ -> else-branch
end match`, with an empty else branch when none is written. The pattern is
anything a match arm accepts, or-patterns included (`if let Red | Green = c
then`); it takes no `when` guard. `else if` and `else if let` chain as they
do after a plain `if`. As an expression it needs an else branch, like any if
expression: `let n = if let Some(x) = o then x else 0 end if`.

### 6.5 While Loop
```geno
while <condition> do
    <body>
end while
```

`break` exits the loop immediately. `continue` skips to the next iteration:
```geno
while x < 10 do
    if x == 5 then
        break
    end if
    x = x + 1
end while
```

### 6.6 For Loop
```geno
for <var>: <type> in <iterable> do
    <body>
end for

for <var> in <iterable> do
    <body>
end for
```

Without `: <type>`, the variable has the iterable's element type.

*Unreleased (proposal 0026):* a tuple pattern of names unpacks each element,
which must be a tuple of matching arity; `_` skips an element and patterns
nest:
```geno
for (i, word) in words.enumerate() do
    print(f"{i}: {word}")
end for

for (k, (a, _)): (String, (Int, Int)) in pairs do
    ...
end for
```

The pattern may contain only names, `_` and nested tuple patterns. Hidden
bindings introduced by unpacking do not capture user identifiers. Tuple
loops support `break`, `continue` and `await` like ordinary loops.

`break` and `continue` are also supported in `for` loops:
```geno
for x: Int in [1, 2, 3] do
    if x == 2 then
        continue
    end if
    print(x)
end for
```

### 6.7 Match Statement
```geno
match <expr> with
    | <pattern1> -> <body1>
    | <pattern2> -> <body2>
    | _ -> <default_body>
end match
```

Example:
```geno
match opt with
    | Some(x) -> return x
    | None -> return 0
end match
```

### 6.8 Return Statement
```geno
return <expr>
return ()        // Return unit
```

### 6.9 Errors and Panics

Geno has one error model. A failure the caller should handle is a value: the
function returns `Result[T, E]` (or `Option[T]` when there is nothing to say
about the failure), and the caller matches on it, propagates it with `?`
(section 7.16), or uses a combinator such as `map_err` or `unwrap_or`:

```geno
@untested("reads the filesystem")
func word_count(path: String) -> Result[Int, String] with fs
    let text = fs_read_text(path)?
    return Ok(length(split(text, " ")))
end func
```

A situation the program cannot recover from is a bug, and ends the program
with a *panic*: a call of `panic(message)` (section 7.14), and every runtime
error — an index out of range, division by zero, `unwrap` on `None`, a failed
`requires`/`ensures`, an exceeded resource limit. Geno code cannot observe or
recover from a panic. The host reports it as an uncaught runtime error: a
Geno-facing diagnostic and a nonzero status (section 6.9.1).

*New in 0.7.* A resource limit ends a program the way a panic does, but it is
not one for a panics example (section 5.3.1): exhausting the step, time,
recursion, memory, collection, integer or output limit never satisfies
`example <inputs> panics`, and neither does a host refusal (E412, E413, E500).

`throw`, `try` and `catch` were removed in Geno 0.6
([proposal 0009](../proposals/0009-result-only-errors.md)). Each is rejected
with E205 and a message naming its replacement.

#### 6.9.1 Runtime Failure Reports

*New in 0.7 (proposal
[0018](../proposals/0018-runtime-failure-diagnostics.md), Accepted).* Every
runtime failure (a panic, a runtime error, a failed `requires` or `ensures`, a
capability or host-policy denial, and a resource limit) is reported with the
place it happened and the Geno calls that led there. This holds on every
`geno run` lane, in `geno test`, the embedding API and the hosted server, and
in standalone compiled Python and Node entry builds. Given `panic.geno`:

```geno
func check(n: Int) -> Int
    example 1 -> 1
    if n > 5 then
        panic("value too large")
    end if
    return n
end func

func scale(n: Int) -> Int
    example 2 -> 4
    return check(n * 2)
end func

func main() -> Int
    return scale(4)
end func
```

`geno run panic.geno` prints this, with the program's absolute path shortened
here to its name:

```text
Stack trace (most recent call last):
  panic.geno:15:12 in main
  panic.geno:11:12 in scale
  panic.geno:4:9 in check
      panic("value too large")
      ^
Runtime Error: value too large
```

- **Frames.** A frame is an activation of a named Geno function: a top-level
  function, an impl method (`Type.method`) or a function of an imported
  module (`Module.function`, the standard library included). Lambdas,
  builtins, runtime helpers and the host are not frames; a lambda runs as
  part of the frame that called it. Frames are listed outermost first, so the
  last one is the most recent call. While an `example` is being verified, the
  outermost frame is `<example>`, positioned at the example clause; when a
  call made by a `test` block fails, the outermost frame is `<test>`,
  positioned at that call. In `geno test` a `test` block's failure has the
  message `Runtime Error: <message>`, with no location in it. 0.6 started a
  located failure's message (an index, key, division or contract failure)
  with its `<file:line:col>: `, a host path; `location` and `stack` carry it
  now.
- **Positions.** Each frame is positioned inside its own function: at the
  call that started the next frame, or, for the innermost frame, at the
  failure. The failure is located at the `panic` or failing builtin call, the
  failing index, key, division or arithmetic expression, or, for a contract,
  the clause's condition. A callback that a builtin calls (`map(xs, g)`) was
  started by that builtin call, and a call made inside a lambda is located in
  the lambda's body. A default parameter value is evaluated in the callee's
  frame: the caller is positioned at the call and the callee at the default
  expression. `main` has no caller, so its frame is the first.
- **Async functions.** An `async` function's frame exists while its body
  runs, which on the interpreter and compiled Python is when its `Async` is
  awaited. The awaiting frame is positioned at the awaited call when `await`
  wraps the call directly (`await load(5)`), and otherwise at the `await`
  expression. Compiled JavaScript starts an async function at its call, so
  when an `Async` is created in one statement and awaited in another, a
  failure before the callee's first suspension positions the caller at the
  creation call there. With `await f(...)` written as one expression, every
  backend gives the same position. For the same reason a failing `Async`
  that nothing awaits ends a Node program with status 1, and never runs on
  the interpreter or compiled Python.
- **Bounds.** A stack of more than 20 frames keeps its first 10 and its last
  10, with `  ... N frames omitted ...` (`1 frame omitted`) between them.
- **Paths.** The CLI lanes print the path the frontend assigned to each file,
  an absolute path for a file on disk. Compiled artifacts print paths
  relative to the entry file's directory, so they do not carry the build
  machine's layout. A file of the standard library is shown as
  `std/<Name>.geno` in every report, text and JSON, so a failure inside the
  library never names the installed library's host path.
- **Layout.** The frame lines come first. Then, where the host can read the
  program's source (the CLI lanes; compiled artifacts carry none), the source
  line the failure points at, with a caret under its column. The
  `<Label>: <message>` line is always last, so a lane's own lines, such as the
  capability hint of section 9.11.1, follow it directly. With no stack but a
  location, an `  at <file:line:col>` line takes the frames' place; with
  neither, only the message line is printed, as in 0.6. The label is
  `Runtime Error`; the interpreter lanes keep `Limit Error` and
  `Sandbox Error` for resource limits.
- **Contract failures.** The message names the function, the call's
  arguments and the clause as written (sections 5.1 and 5.2), and the failure
  is located at the clause. A value is rendered the way `to_string` renders
  it inside a collection, so a string is quoted (`f(s: "0")` is not
  `f(s: 0)`), and is cut to 64 code points (61 and `...`). The clause text has
  its comments removed and its whitespace collapsed, and is cut to 200 code
  points. The values shown are always the call's arguments, as the callee
  received them (after defaults and `Int`-to-`Float` widening). An `ensures`
  clause sees a parameter as it is when the function returns, which a
  top-level rebinding in the body (`let n = n + 5`) changes. When a
  parameter's value at the check differs from its argument, the message adds
  it after the result,
  `Postcondition failed: g(n: 1) ensures n > 10 (result was 6; n was 6 when checked)`,
  and the JSON `contract` lists it in `checked_values`. A binding of the same
  name in a nested block does not rebind the parameter and adds nothing.
- **Messages stay messages.** The location and the stack are never part of
  the message. A `panics "substring"` example (section 5.3.1) and a property
  check (section 5.4) read only the message, so no file name, position or
  frame name can satisfy one.
- **JSON.** A runtime failure's diagnostic in `geno run --json`, the
  embedding API and the hosted server, and a `geno test --json` violation,
  carry `location` and a `stack` list of `{"function", "location"}` objects,
  outermost first (a frame without a position has no `location`), and
  `stack_omitted` when frames were left out; those lie between the 10th and
  the 11th entry. A contract failure's diagnostic adds `contract`
  (section 5.4). JSON paths are the frontend's own, except that a
  standard-library file is `std/<Name>.geno` there too. The keys are
  additive: codes, exit statuses and every existing key are unchanged, and
  so is every existing value but one: a `geno test` violation's `message`
  for a located failure in a `test` block, or in a file that fails while
  loading, drops the `<file:line:col>: ` that 0.6 put before
  `Runtime Error:`.
- **Compiled backends.** Compiled Python and JavaScript find positions when a
  failure escapes `main`, from a table the compiler embeds in the generated
  file, so no call does extra work and the artifact still needs no Geno
  install. They agree with the interpreter on panics, `unwrap` and `expect`,
  indexing, division, contract checks, calls (calls through function values
  and default parameter values included), callbacks and lambdas. In a
  statement where two of its operations could have made the failing call,
  they report the statement's start, never a call that was not the one
  failing: two operations of the same kind, such as `xs[i] + ys[j]` or two
  calls through function values, and a call of a function or builtin by name
  next to a call through a function value, which could hold the same
  function (`check(1) + f(9)`). A parameter or local that shadows a function
  or builtin name, such as a callback parameter called `format`, is a
  function value. Their index and division messages keep their 0.6 wording
  (`Index 3 out of bounds`, where the interpreter adds
  `for list of length 3`). A host stack overflow's depth, message and
  innermost frame are the host's: the innermost frame is where the host ran
  out of stack, at the recursive call or inside the callee's first operation,
  and every other kept frame is the same on every backend
  (`RangeError: Maximum call stack size exceeded` on Node). Browser builds and
  programs without `main` embed no table and report as in 0.6.
- **Host tracebacks.** With `GENO_TRACEBACK=host` in its environment, a
  `geno run` lane, a standalone compiled Python program and a Node entry
  build also print the host's own traceback after the report, under
  `Host traceback (GENO_TRACEBACK=host):`, for debugging Geno itself (before
  any capability hint). JSON envelopes, the embedding API and the hosted
  server ignore it, and no Geno program can read it.
- **What cannot be reported.** A hard wall-clock kill or a memory exhaustion
  of the default lane's worker leaves no reporter running, and reports its
  message alone. An `Err` returned from `main` is not a runtime failure
  (section 4.1.1).

### 6.10 Import Statement
```geno
import ModuleName
import ModuleName as Alias
```

An import makes the imported module's exported functions available unqualified
(unless aliased) and as `ModuleName.name`, and its exported types available by
name. It does not make visible what the imported module itself imports: a
program that calls a function from module `A` must import `A`, even when it
also imports a module that imports `A`. An imported module sees the builtins,
its own definitions, and its own imports, never the definitions or imports of
the program that imported it.

An unqualified import of a standard-library module does not bind a name that
is an always-available builtin: `import List` leaves `length` the builtin
(which also takes a `String`), and `List.length` stays available qualified.

## 7. Expressions

### 7.1 Literals
```geno
42              // Int
3.14            // Float
"hello"         // String
f"Hi {name}"    // F-string (interpolated)
true            // Bool
[1, 2, 3]       // List
(1, "a", true)  // Tuple
()              // Unit
```

A list literal's element type is the common type of its elements, widening
`Int` to `Float` in any order. An element whose type is still open (`None`,
`[]`, `Err(e)`, or a nullary constructor of a generic type such as `Leaf`)
takes the rest of its type from the other elements: `[None, Some("s")]` is a
`List[Option[String]]`, so it cannot be bound to a `List[Option[Int]]`.

### 7.1.1 F-String Interpolation

F-strings allow embedding expressions inside string literals:
```geno
let name: String = "Alice"
let age: Int = 30
let greeting: String = f"Hello {name}, you are {age} years old"
```

Expressions inside `{...}` are evaluated and converted to strings. Escape
sequences (`\n`, `\t`, `\\`, `\"`) are supported in the text portions. Braces
inside an expression, outside a string literal, are not allowed.

*Unreleased (proposal 0026):* an expression may contain string literals,
whose text may hold braces, quotes and other f-strings:
`f"{m.get("the", 0)} {s.replace("}", "")}"`. Earlier releases rejected any
string literal inside an expression. Nesting string literals and f-strings
inside interpolations is limited to 50 levels; deeper input is a diagnostic.

*Unreleased (proposal [0023](../proposals/0023-format-specs-slices-named-patterns-if-let.md), Accepted).* An interpolation may end with
a format spec after a colon, `f"{price:.2f}"`:

```
[[fill]align][sign][0][width][,][.precision][type]
```

| Part | Meaning |
|------|---------|
| `align` | `<` left, `>` right, `^` centre, with an optional `fill` character before it (a space otherwise) |
| `sign` | `+` always writes a sign, a space writes one for non-negative numbers, `-` is the default |
| `0` | pads a number with zeros after its sign |
| `width` | the least number of characters written, at most 1000 |
| `,` | groups the digits of the whole part in threes; with `d` and `f` |
| `.precision` | decimals for `f`, `e` and `%` (6 when left out), or the number of characters kept for text; at most 100 |
| `type` | `d` decimal, `x` and `X` hexadecimal, `o` octal, `b` binary, for an Int; `f` fixed, `e` exponent, `%` percent, for an Int or a Float; `s` for any value |

Without a type an Int is written like `d`, and any other value is the text
`to_string` writes, padded and cut by the spec; a Float then takes only a
fill, an alignment and a width. A number is right-aligned and other text
left-aligned unless the spec says otherwise. The `0` flag takes no alignment
and no `,`.

```geno
f"{n:5}"          // "   42"
f"{n:05d}"        // "00042"
f"{total:,}"      // "1,234,567"
f"{ratio:.1%}"    // "12.5%"
f"{name:>10}"     // "     Alice"
f"{x:.2f}"        // "3.14"
```

The spec starts at the first `:` outside brackets and string literals, so
the colon of a named argument, a slice or a map key inside the expression is
not that one. Every backend writes what Python's `format` writes for the same
spec and value, including a tie, which rounds to the even digit:
`f"{2.5:.0f}"` is `"2"`. A spec that is malformed or does not fit the type of
its value is a type error (E331).

### 7.1.2 Map Literals

```geno
let ages = {"ada": 36, "alan": 41}
let empty: Map[String, Int] = {}
```

`{k1: v1, k2: v2, ...}` is a `Map` whose key type is the common type of its
keys and whose value type is the common type of its values, widening `Int` to
`Float` and completing open types as list elements do. `{}` is an empty map whose types come from
context. Keys must be hashable. Two keys written as equal literals are
rejected. Entries are inserted in source order. A trailing comma is allowed.

### 7.2 Arithmetic Operators
```geno
x + y           // Addition
x - y           // Subtraction
x * y           // Multiplication
x / y           // Division (truncation-toward-zero for Int, float for Float)
x % y           // Modulo (truncation-toward-zero: sign follows dividend)
x ** y          // Exponentiation (right-associative: 2 ** 3 ** 2 == 2 ** 9)
-x              // Negation
xs + ys         // List concatenation
```

`+` also concatenates two `String`s, and two lists of one element type
([proposal 0012](../proposals/0012-what-models-reach-for.md)): `[1] + [2, 3]`
is `[1, 2, 3]`, `[] + xs` takes the type of `xs`, and a `List[Int]` joins a
`List[Float]` as Floats. The collection-size limit applies as it does to
`concat`.

The `divide` builtin follows the operand types: integer operands truncate
toward zero, while Float operands retain the fractional result.

### 7.2.1 Bitwise Operators
```geno
x & y           // Bitwise AND (Int only)
x ^ y           // Bitwise XOR (Int only)
x << y          // Left shift (Int only)
x >> y          // Right shift (Int only)
~x              // Bitwise NOT (unary, Int only)
bit_or(x, y)    // Bitwise OR (builtin function, Int only)
```

Shift operators bind tighter than `&`, and `&` binds tighter than `^`. Bitwise
expressions bind tighter than comparisons, so `a & b == 0` parses as
`(a & b) == 0`.

### 7.3 Comparison Operators
```geno
x == y          // Equal
x != y          // Not equal
x < y           // Less than
x > y           // Greater than
x <= y          // Less or equal
x >= y          // Greater or equal
x in c          // Membership
x not in c      // not (x in c)
```

Equality between an `Int` and a `Float` is numeric, so `2 == 2.0` is `true`.
Structural equality applies the same rule recursively within compound values.

`x in c` tests membership and has type `Bool`
([proposal 0012](../proposals/0012-what-models-reach-for.md)). The operands are
evaluated left to right:

| `c` | `x` | True when |
| --- | --- | --- |
| `List[T]`, `Set[T]` | `T` | an element equals `x` |
| `String` | `String` | `x` is a substring of `c` |
| `Map[K, V]`, `MutableMap[K, V]` | `K` | `x` is a key of `c` |

Any other `c` is rejected (E300). In a `for` header or a comprehension's
`for` clause, `in` after the loop variable belongs to the loop.

Comparisons are non-associative: `a < b < c` is invalid. Write
`a < b and b < c` instead.

### 7.4 Logical Operators
```geno
a and b         // Logical AND
a or b          // Logical OR
not a           // Logical NOT
```

### 7.5 Function Calls
```geno
// Positional arguments (up to 2 params)
add(1, 2)
length(items)

// Named arguments (required for 3+ params)
make_point(x: 10, y: 20, z: 30)
configure(host: "localhost", port: 8080, timeout: 30)
```

### 7.5.1 Method Calls

`receiver.name(args)` calls a function with the receiver as its first
argument:

```geno
let total = [3, 1, 2]
    .map(fn(x: Int) -> x * 10)
    .fold(initial: 0, reducer: fn(acc: Int, x: Int) -> acc + x)
let label = " ada ".trim().to_upper()
let first = Some(4).unwrap_or(0)
```

When `receiver` names an imported module, the call is a qualified call
(section 6.10). Otherwise, with `R` the receiver's type:

1. If `R` is a user-defined type with a field `name`, the call calls that
   field's function value.
2. Otherwise the call is `F(receiver, args)` for the first function `F` found
   in this order:
   1. the trait method `name`, when `R` implements a trait that declares it, or
      `R` is a type parameter bounded by such a trait;
   2. a top-level function `name` the program defines or imports (and that no
      two imports both export) whose first parameter accepts `R`;
   3. the builtin `<prefix>_name`, where the prefix is `list` for `List`,
      `option` for `Option`, `result` for `Result`, `map` for `Map`,
      `mutable_map` for `MutableMap`, `vec` for `Vec`, `array` for `Array`,
      `set` for `Set`, `string` for `String`, `int` for `Int` and `float`
      for `Float` (`n.to_float()` is `int_to_float(n)`);
   4. the builtin `name` whose first parameter accepts `R`; `length` accepts a
      list, a string, or an array, and on a `Map`, `Set` or `MutableMap` is
      `map_size`, `set_size` or `mutable_map_size`, so every collection has
      `length()`.
3. If there is no such function, the call is rejected (E307).

**Free calls.** A call `name(x, args)` that names a top-level function or
builtin whose first parameter cannot accept `x` is the call `x.name(args)`
would make, when that is a different function: `map(opt, f)` calls
`option_map`, `length(m)` calls `map_size`. The rule applies only where the
call would otherwise be rejected, so it changes the meaning of no accepted
program; when no function accepts `x`, the original mismatch is reported
([proposal 0010](../proposals/0010-coherent-standard-library.md)).

The receiver is `F`'s first argument in type checking and generic
instantiation. The named-argument rule (section 11) counts only the arguments
written after the receiver, so `xs.fold(0, f)` and `s.replace("a", "b")` stay
positional. Local variables are never chosen as methods.

### 7.6 Lambda Expressions

Inline lambdas (single expression):
```geno
fn(x: Int) -> x * 2
fn(a: Int, b: Int) -> a + b
fn() -> 42
```

Block lambdas (multiple statements):
```geno
fn(x: Int) do
    if x > 0 then
        return x * 2
    else
        return 0
    end if
end fn
```

Block lambdas support all statement forms (`if`, `while`, `for`, `match`, etc.)
and their return type is inferred from `return` statements.

A lambda is its own unit for effects (section 3.5; changed in 0.7 by proposal
[0019](../proposals/0019-local-mutation-is-not-an-effect.md), Accepted).
Assigning a variable declared in the lambda's own body is not an effect. A
lambda that assigns a variable captured from an enclosing scope carries
`mutation`, because successive calls of the closure observe the change;
creating the lambda is not an effect, so the enclosing function is not
charged for it:

```geno
@untested("returns a closure")
func make_counter() -> () -> Int with mutation
    var n = 0
    return fn() do
        n = n + 1      // captured: the lambda carries `mutation`
        return n
    end fn
end func
```

`make_counter` itself is pure, but its declared return type must say
`with mutation`; `-> () -> Int` is rejected (E300).

A lambda parameter may omit its type when the lambda's context expects a
function type: a call parameter, a pipeline stage's argument, an annotated
`let` or `var`, a `return` whose declared type is a function type, or a
constructor field. The parameter takes the corresponding parameter type of the
expected function type:

```geno
let doubled = [1, 2, 3].map(fn(x) -> x * 2)
let total = [1, 2, 3].fold(initial: 0, reducer: fn(acc, x) -> acc + x)
let inc: (Int) -> Int = fn(x) -> x + 1
```

Within a call or a pipeline stage, a lambda with an unannotated parameter is
checked after the piped value and the other arguments, so their types are
available to it: in `xs |> fold(_, 0, fn(acc, x) -> acc + x)`, `acc` is `Int`
and `x` is the element type of `xs`. A lambda parameter
whose context does not determine its type is rejected (E321).

### 7.7 Pipeline Expressions
Left-to-right data flow:
```geno
[1, 2, 3, 4, 5]
    |> filter(_, fn(x: Int) -> x % 2 == 0)
    |> map(_, fn(x: Int) -> x * x)
    |> fold(_, 0, fn(acc: Int, x: Int) -> acc + x)
```

The `_` placeholder indicates where the previous value is inserted.

```geno
Some(42)
None
Point(x: 10, y: 20)
Cons(1, Nil)
```

### 7.9 Index Access
```geno
items[0]            // First element
items[-1]           // Last element (negative indexing)
items[-2]           // Second to last
matrix[i][j]
```

Negative indices count from the end: `-1` is the last element, `-2` is
second-to-last, etc. Out-of-bounds indices (including negative indices that
exceed the length) raise a runtime error.

#### 7.9.1 Slices

*Unreleased (proposal [0023](../proposals/0023-format-specs-slices-named-patterns-if-let.md), Accepted).* A slice takes part of a List
or a String:

```geno
xs[1:3]     // from index 1 up to, not including, index 3
xs[2:]      // from index 2 to the end
xs[:2]      // the first two
xs[:]       // all of it
xs[-2:]     // the last two
s[1:-1]     // a String without its first and last character
```

Each bound is an Int. A negative bound counts from the end, and a bound past
either end is clamped, so a slice never fails: `[1, 2, 3][1:99]` is `[2, 3]`
and `xs[4:2]` is empty. A String slices by code point, like indexing. The
result has the type of what was sliced. Other types cannot be sliced, and a
step (`xs[::2]`) is a parse error; use `reverse` or a comprehension.

A tuple's elements are indexed with a literal: `pair.0`, `pair.1`, or
equivalently `pair[0]`. The index must be an integer literal less than the
tuple's arity, and the result has that element's type. A nested field needs
parentheses, `(t.0).1`, because `t.0.1` would read `0.1` as a number.

Map indexing is also partial: `m[key]` returns the value or raises a Geno
runtime error when the key is absent. Use `map_get(m, key)` when absence is
expected and should be represented as `Option[V]`.

### 7.10 Field Access
```geno
point.x
person.name
```

### 7.11 Match Expression
```geno
let result: Int = match opt with
    | Some(x) -> x
    | None -> 0
end match
```

Match arms support optional guard conditions with `when`:
```geno
let label: String = match value with
    | x when x > 0 -> "positive"
    | x when x < 0 -> "negative"
    | _ -> "zero"
end match
```

Guards are evaluated after the pattern matches. If the guard is false, the
next arm is tried.

### 7.11.1 If Expression

```geno
let parity = if n % 2 == 0 then "even" else "odd" end if
let label = if score >= 90 then
    "excellent"
else if score >= 60 then
    "passing"
else
    "needs work"
end if
```

In expression position, `if` starts an if expression. Each branch is a single
expression and the `else` branch is required. It means
`match condition with | true -> a | false -> b end match`: the condition must
be `Bool`, and the branches need a common type, as the arms of a match
expression do.

### 7.12 With Expression

Functional record update — creates a modified copy of a value:
```geno
let moved: Player = player with (x: player.x + 1, y: player.y + 2)
```

The original value is unchanged. Only the specified fields are updated in the copy.

### 7.13 List Comprehensions

Concise syntax for transforming and filtering lists:
```geno
let doubled: List[Int] = [x * 2 for x: Int in numbers]
let evens: List[Int] = [x for x: Int in numbers if x % 2 == 0]
```

Syntax: `[element_expr for var: Type in iterable]` or
`[element_expr for var: Type in iterable if condition]`. `: Type` may be
omitted, giving the variable the iterable's element type.

*Unreleased (proposal 0026):* the variable may be a tuple pattern of names, as
in a `for` loop (section 6.6): `[k for (k, v) in m.entries() if v > 1]`.
A tuple-pattern comprehension cannot use `await` in its element or filter
(outside a nested lambda); use a tuple-pattern `for` loop instead.

The iterable must be a `List[T]`. The condition (if present) must be `Bool`.
The result type is `List[U]` where `U` is the type of `element_expr`.

### 7.14 Panic

`panic(message: String)` ends the program with `message` (section 6.9). Its
result type is `Never`, which fits wherever a value is expected, so a panic
can complete a branch of an `if` or `match` expression; a statement that is a
call of type `Never` ends its path for return-path analysis (section 10.3):

```geno
func half(n: Int) -> Int
    example 4 -> 2
    if n % 2 == 0 then
        return n / 2
    end if
    panic("half expects an even number")
end func
```

The interpreter reports a panic with E414. `r.unwrap()` and `r.expect(message)`
panic on `Err`, and `opt.unwrap()` and `opt.expect(message)` on `None`
(section 9.2).

*New in 0.7 (proposal
[0018](../proposals/0018-runtime-failure-diagnostics.md), Accepted).* Every
backend reports a panic located at the `panic` call (or the failing `unwrap`
or `expect`), with the Geno stack that reached it (section 6.9.1). The
diagnostic's message is exactly `message`, with no location or stack in it.

### 7.15 Await Expression

Resolves an `Async[T]` value, producing the inner `T`:
```geno
let data: String = await fetch("https://example.com")
```

`await` may only appear inside `async func` or `main()`. In the interpreter,
`await` executes the deferred computation synchronously. In compiled output,
it maps to the target language's native `await`.

An `Async[T]` value runs its computation at most once. Awaiting the same value
again, including while an earlier await of it is still in progress, produces
the result of that one run; if the run panics, the program ends:
```geno
let a = load(1)        // load is an async func
let x = await a        // runs load once
let y = await a        // reuses that result; load does not run again
```

### 7.16 Propagation Operator (`?`)

The `?` operator unwraps `Option` or `Result` values, returning early from the
enclosing function on failure:
```geno
func get_name(data: Option[String]) -> Option[String]
    let name: String = data?    // returns None if data is None
    return Some(name)
end func
```

For `Option[T]`:
- If the value is `Some(x)`, unwraps to `x`
- If the value is `None`, immediately returns `None` from the enclosing function

For `Result[T, E]`:
- If the value is `Ok(x)`, unwraps to `x`
- If the value is `Err(e)`, immediately returns `Err(e)` from the enclosing function

### 7.17 Typed Holes

Typed holes are placeholders for expressions that are not yet implemented.
They let the type checker verify the rest of the program while marking gaps:
```geno
let x: Int = ?todo: Int
let y: String = ?name: String where length(name) > 0
```

Syntax: `?name: Type` or `?name: Type where constraint`.

At runtime, evaluating a typed hole raises an error. They are intended for
incremental development and LLM-assisted code generation.

## 8. Patterns

### 8.1 Variable Pattern
Binds matched value to a name:
```geno
| x -> ...
| value -> ...
```

### 8.2 Wildcard Pattern
Matches anything, discards value:
```geno
| _ -> ...
```

### 8.3 Literal Pattern
Matches specific value:
```geno
| 0 -> "zero"
| 1 -> "one"
| "hello" -> "greeting"
```

### 8.4 Constructor Pattern
Matches and destructures:
```geno
| Some(x) -> x
| None -> default
| Cons(head, tail) -> head
| Point(x, y) -> x + y
```

#### 8.4.1 Named Fields

*Unreleased (proposal [0023](../proposals/0023-format-specs-slices-named-patterns-if-let.md), Accepted).* A constructor pattern may
name the fields it matches, in any order, each at most once. `..` after the
last one ignores the fields that are not named:

```geno
| Cfg(port: p, ..) -> p
| Cfg(debug: true, host: h, ..) -> h
| Rect(h: h, w: w) -> w * h
```

A pattern names all of its fields or none. Without `..` every field must be
named; a field the constructor does not have, or one left out, is a type
error that lists the constructor's fields. An ignored field matches
anything, as `_` does, for exhaustiveness too.

### 8.5 List Pattern
```geno
| [] -> "empty"
| [x] -> "single"
| [x, y] -> "pair"
```

### 8.6 Tuple Pattern
Matches and destructures a tuple. The pattern's arity must equal the tuple
type's arity, and tuple patterns need at least two elements:
```geno
| (a, b) -> a + b
| (x, _, z) -> x + z
| Some((key, value)) -> key       // nested inside a constructor pattern
```

Because every value of a tuple type has that type's arity, a single tuple
pattern whose elements are all variables or wildcards is exhaustive and needs
no default arm.

### 8.7 Rest Pattern (Spread)
Matches the remaining elements of a list:
```geno
| [head, ...tail] -> head       // tail binds to remaining elements
| [first, second, ...rest] -> first + second
| [x, ...] -> x                // anonymous rest (discards remainder)
```

The rest pattern must appear at most once per list pattern. Elements after
the rest pattern match from the end of the list.

### 8.8 Or-Patterns
An arm may list alternative patterns separated by `|`; it matches when any of
them does:
```geno
| Red | Orange -> return "warm"
| Circle(r) | Ring(r) -> r
```

Every alternative must bind the same variable names. The arm behaves as one
arm per alternative with the same guard and body: exhaustiveness counts each
alternative, and in each, a binding has the type that alternative gives it.

string is non-empty and every character is an ASCII digit, letter, letter or
digit, whitespace character, uppercase letter, or lowercase letter, so every
backend agrees.


`square`, `is_positive`, `is_sorted`, `is_permutation`, `is_numeric_string`,

### 9.11 Capability-Gated Builtins

The following builtins require explicit capability grants (via `--cap` on the
CLI or the embedding API). They are unavailable by default, except that plain
`geno run` grants `print`, `clock` and `random`; section 9.11.1 states which
grants each `geno run` lane accepts.

```geno
// Print (requires "print")
print(value)                    // -> Unit

// Clock (requires "clock")
clock_now()                     // -> Int (Unix timestamp in seconds)
clock_format(timestamp: Float, fmt: String) // -> String (strftime format)
clock_parse(text: String, fmt: String) // -> Option[Float] (parse to timestamp)
clock_elapsed(start: Float, end: Float) // -> Float (seconds between timestamps)
sleep_ms(ms)                    // -> Unit

// Random (requires "random")
random_int(lo, hi)              // -> Int
random_float()                  // -> Float

// File system (requires "fs")
fs_read_text(path)              // -> Result[String, String]
fs_write_text(path, content)    // -> Result[Unit, String]
fs_list_dir(path)               // -> Result[List[String], String]
fs_exists(path)                 // -> Bool
fs_metadata(path)               // -> Result[FileMetadata, String] (follows final link)
fs_symlink_metadata(path)       // -> Result[FileMetadata, String] (does not follow final link)
fs_canonicalize(path)           // -> Result[String, String] (existing absolute real path)

// HTTP (requires "http")
http_fetch(url)                 // -> Result[String, String]
http_post(url, body)            // -> Result[String, String]
http_request(method, url, headers, body) // -> Result[HttpResponse, String]

// Regex (requires "regex")
regex_match(pattern, text)      // -> Option[String] (first match)
regex_find_all(pattern, text)   // -> List[String] (all matches)
regex_replace(pattern, repl, text) // -> String

// Environment variables and program arguments (requires "env")
env_get(name)                   // -> Option[String]
env_get_or(name, default)       // -> String
cli_args()                      // -> List[String] (program arguments)

// Process execution (requires "process")
exec(command)                   // -> Result[ProcessResult, String]
exec_with_input(command, stdin) // -> Result[ProcessResult, String]
spawn(program, args)            // -> Result[ProcessResult, String]
spawn_with_input(program, args, stdin) // -> Result[ProcessResult, String]

// Standard input (requires "stdin")
stdin_read_all()                // -> String
```

`ProcessResult`, `HttpResponse`, `FileKind`, and `FileMetadata` are built-in
types (see [3.2.2](#322-built-in-adt-types)). Filesystem metadata reports the
host byte-size field and the modification time in whole Unix milliseconds,
rounded down. Canonical paths use `/` separators on every host. Ordinary OS and
configured-root policy failures return `Err`; capability and portable resource
violations remain runtime errors, with one exception: the write quotas of the
isolated `geno run` lane (section 9.11.1) make `fs_write_text` return `Err`.
The browser target does not provide these filesystem operations.

Process commands are split via `shlex.split` (Python) and run with a 30-second
timeout. In JS compiled output, `exec` returns `Err("process execution not
available in browser context")`.

Across the Python interpreter, compiled Python, and compiled Node targets,
`http_fetch`, `http_post`, and `http_request` require only the `http`
capability. `http_post` sends its UTF-8 body as `application/json`.
`http_request` accepts and returns ordered `List[(String, String)]` header
pairs, including duplicate response headers.

Every received HTTP status is a response: `http_fetch` and `http_post` return
`Ok` with its body, while `http_request` returns `Ok(HttpResponse)`. Scheme,
transport, redirect-policy, and network-policy failures return `Err` from all
three. Responses are decoded as
UTF-8 and streamed to the runtime collection limit.

Only `http` and `https` URLs are allowed. Resolved loopback, private,
link-local, multicast, reserved, and unspecified addresses are denied by
default; every redirect is revalidated, at most ten redirects are followed,
and all caller headers are removed on a cross-origin redirect. Trusted hosts
may opt into private targets with `GENO_HTTP_ALLOW_PRIVATE=1`. Compiled Node's
internal child bridge receives request data over stdin and does not grant the
Geno program the `process` capability. Empty bodies on `GET` and `HEAD` are
omitted.

> **Note:** Regex patterns are limited to 1000 characters for ReDoS
> mitigation. Clock timestamps must be non-negative.

### 9.11.1 Capability Grants in the Isolated `geno run` Lane

*New in 0.7 (proposal
[0013](../proposals/0013-isolated-run-capabilities.md), Accepted).* `geno run`
has three lanes. Before 0.7 the default one refused every `--cap`, so a
program that needed more than `print`, `clock` and `random` had to leave it.

| Lane | Runs | Grant | Limits |
| --- | --- | --- | --- |
| default (`geno run`) | compiled Python in a supervised worker process | the `--cap` list, or `clock`, `print` and `random` without one | hard wall-clock kill at `--timeout`; memory, CPU, file-size and process limits; output shown when the program ends |
| `--unsafe` | the interpreter, in the CLI's own process (trusted code only) | the `--cap` list, or `clock`, `print` and `random` without one | cooperative timeout and step limit |
| `--json` | the embedding API, in the CLI's own process | the `--cap` list; nothing without one | cooperative timeout and step limit |

**Grant.** In the default lane:

- Without `--cap`, examples and `main` get `clock`, `print` and `random`, as
  in 0.6.
- With `--cap`, they get exactly the listed capabilities. The list is not
  added to the defaults: `--cap env` denies `print`.
- Unknown names are rejected, as in every lane. Before any worker starts, the
  CLI refuses each capability the lane cannot grant on this platform. It
  prints one `Error:` line per refused capability, in name order, and exits
  1:
  - `process` and `serve` are never granted here: `Error: --cap process is
    not available in the process-isolated run mode: programs it starts would
    run outside the sandbox. Use --unsafe --cap ... for trusted code.` For
    `serve` the reason is that a listener would outlive the run's wall-clock
    limit and buffered output.
  - A capability whose platform gate has not passed (see the platform table
    below): `Error: --cap stdin is not yet available in the process-isolated
    run mode. Use --unsafe --cap ... for trusted code, or --json --cap ...
    for embedding API execution.` On Windows, `http` gets the same message
    with a first sentence ending `run mode on Windows.` `--json` grants such
    a capability but has no host callbacks for `fs`, `http` or `stdin`, so
    their builtins fail there with E413.
- The worker validates the grant and the host policy its parent sends before
  it reads any program input. An invalid one is a startup error, and the
  program does not run.

**Platforms.** The lane grants:

| Capability | Linux | macOS | Windows |
| --- | --- | --- | --- |
| `clock`, `print`, `random`, `regex` | granted | granted | granted |
| `env` | granted | granted | granted |
| `fs` | granted | granted | granted |
| `http` | granted | granted | refused |
| `stdin` | refused | refused | refused |
| `process`, `serve` | refused | refused | refused |

`stdin` is implemented (below) but stays refused on every platform. Proposal
0013 keeps it refused until its stdin gate has passed on Linux, macOS and
Windows: handle setup, inheritance, and cleanup after a timeout or an
interruption. Only Linux and macOS evidence exists so far, and enabling the
capability on those alone would be a deviation from the gate that needs the
project lead's sign-off. `http` stays refused on Windows until the HTTP gate
has Windows evidence. Programs that need a refused capability use
`--unsafe --cap` (trusted code only).

**Host bindings.** The worker gives a program host access only for the
capabilities it was granted. It builds a private table of trusted bindings,
which the runtime prelude reaches through four names: `_GENO_HOST`,
`_GenoHostUnavailable`, `_geno_host_module` and `_geno_environ`. They are
reserved runtime names on every target (section 2.2.1): the Python and
JavaScript compilers reject a program that defines or references one
(`'_geno_environ' is a reserved runtime name and cannot be used as a function
name`), and so do function and lambda parameters, local bindings, `for`
variables and pattern bindings with one of the names, before any worker
starts. The worker also rejects compiled code that names or binds one. A gated
builtin passes two independent gates: its capability check (E412), and the
presence of its binding, which exists only when the capability is granted.
Bindings hand the program only Geno values, never host objects.

**`env`.**

- `cli_args()` returns the program arguments given after `--`. It needs `env`
  and no allowed variable name.
- `--cap env` alone exposes no environment variable. The repeatable
  `--allow-env NAME` lets `env_get` and `env_get_or` read `NAME` from the
  caller's environment; it takes an exact name, never a pattern. It needs an
  explicit `--cap env` grant, and `--unsafe` and `--json` refuse it (exit 1).
- The CLI sends the worker only the allowed variables the caller has, read
  before the run starts. Reading any other name fails with E412,
  `env_get: environment variable 'NAME' is not allowed by the host env
  policy`, even when the caller does not have it. An allowed name the caller
  does not have gives `None`, or the default for `env_get_or`. The program
  never sees the worker's own environment: with `--allow-env HOME` it reads
  the caller's `HOME`.
- Names are compared exactly on Linux and macOS, as the host's environment
  is. On Windows they are case-insensitive, as `os.environ` is there:
  `--allow-env Path` permits `env_get("PATH")` and `env_get("path")`.

**`fs`.**

- The filesystem builtins go through a narrow trusted facade with exactly
  the root, symlink and absolute-path rules of `--unsafe --cap fs`
  ([capability reference](../reference/capabilities.md#host-resource-scope)).
  The roots are the working directory, the source file's directory, the
  project root and the directories of path arguments after `--`, or
  `GENO_FS_ROOTS`; `GENO_FS_ALLOW_ABSOLUTE` and `GENO_FS_READ_ONLY` apply as
  there. The CLI reads these three variables from the caller's environment
  only when `fs` is granted, and `--allow-env` has no effect on them. With
  `fs` granted, an empty `GENO_FS_ROOTS` stops the run before launch with
  `Error: GENO_FS_ROOTS must contain at least one filesystem root`
  (`--unsafe` reports the same text as a `Runtime Error`). A path argument
  widens the roots under an `fs`-only grant, while `cli_args()` still needs
  `env`.
- `fs_write_text` has two portable limits, enforced on every platform:
  `--max-file-size-bytes` for each write and `--max-total-write-bytes` for
  the run, examples and `main` together. Both default to 64 MiB (67,108,864
  bytes) when `fs` is granted, and to 0 otherwise. They count the UTF-8 bytes
  a write emits after newline translation (each `\n` is two bytes on
  Windows). A write's cost is checked against both limits and reserved before
  the file is opened or truncated, and it is never refunded: a rewrite of the
  same path counts again, and so does a write that then fails. A limit of 0
  disables every write, including an empty one. Content that cannot be
  encoded as UTF-8 (a lone surrogate) costs 0 bytes and behaves as in
  `--unsafe` and compiled Python: the destination is truncated, or created,
  empty, and the write returns the encoding error as `Err`.
- A quota rejection returns `Err` naming the limit, for example
  `fs_write_text: writing 11 bytes exceeds the per-file limit of 4 bytes
  (--max-file-size-bytes)`, and leaves the destination unchanged, so the
  program can recover and continue (the exception noted in section 9.11). A
  write in read-only mode still raises, as in the other lanes.
- Where the host supports it, the per-file limit is also the worker's
  `RLIMIT_FSIZE`. The limits never grant `fs` or bypass read-only mode. Both
  flags configure the process sandbox, and `--unsafe` and `--json` refuse
  them, even when they are 0.

**`http`.**

- `http_fetch`, `http_post` and `http_request` use the same validated client
  as `--unsafe --cap http`, run in the worker's trusted code. Section 9.11's
  rules apply unchanged: only `http` and `https`, destination checks on every
  connection and redirect, at most ten redirects, caller headers removed
  across origins, TLS verification, and response bodies read against the
  collection limit. Proxy variables never reroute a request.
- Private and loopback destinations need `GENO_HTTP_ALLOW_PRIVATE=1` in the
  caller's environment. The CLI reads it only when `http` is granted, and
  `--allow-env` cannot enable it.
- TLS trusts what it trusts under `--unsafe`: with `http` granted, the CLI
  passes the caller's `SSL_CERT_FILE` and `SSL_CERT_DIR`, when set, to the
  worker, where the TLS library reads them as it does in the CLI's own
  process. Without `http` neither is read or passed, and the program cannot
  read them in either case.
- Each connection attempt and redirect hop waits at most 30 seconds, and at
  most the time the run has left. Name resolution has no cooperative timeout;
  the hard kill at `--timeout` ends any request that cannot finish in time.
- The worker loads the HTTP client during its trusted setup only when `http`
  is granted.

**`stdin`** (implemented; refused until its gate passes, see the platform
table):

- Only a `stdin` grant passes the worker a handle to the caller's standard
  input. Nothing is read until `stdin_read_all()` asks, so a run that never
  calls it, or whose grant is refused, consumes no input.
- The worker reads 8,192 bytes at a time under the run's deadline, checks the
  collection limit after each chunk and decodes strict UTF-8. Invalid UTF-8
  returns the same `Err` text as standalone compiled Python. Over-limit input
  fails with `String size exceeds limit (N > M)`, where N is the number of
  characters decoded when the limit was detected (`M < N <= M + 8192`), not
  the total length of the input, which standalone output reports. Because the
  size is checked chunk by chunk, input that crosses the limit before an
  invalid byte gets the size error, where standalone output and `--unsafe`
  return the UTF-8 `Err`.
- Examples and `main` read one stream. Input an example consumes is not
  replayed, and a read after the end of input returns `""`.

**Examples.** Examples run before `main` with the same grant and the same
bindings: one environment snapshot, one filesystem facade and write budget,
one HTTP policy and one stdin stream. Their authorized effects are real and
are not undone. They run in the time left of `--timeout`, not a fresh
allowance, and timeout messages still name `--timeout`. Their output is never
shown, but it counts against `--max-output-length`, which `main` then shares.
`--max-steps` still applies only to the interpreter lanes, and
`--no-check-examples` skips examples together with their effects. Effectful
code is easiest to check as a pure helper that takes its data as arguments
and carries the examples, called by a thin wrapper that does the I/O.

**Diagnostics.** A denial is E412 in examples and in `main`. It is reported
like every runtime failure (section 6.9.1), located at the gated builtin's
call, with the Geno stack mapped back from the worker's compiled `main`; no
worker, sandbox or runtime frame appears. When the lane can grant the missing
capability, the hint follows the report and keeps the program isolated. For a
`main.geno` that calls `print(cli_args())` on line 2:

```text
Stack trace (most recent call last):
  main.geno:2:11 in main
      print(cli_args())
            ^
Runtime Error: Capability denied: 'cli_args' requires the 'env' capability
Hint: grant it with --cap; the program stays process-isolated:
  geno run --cap clock,env,print,random main.geno -- hello
```

For a capability the lane cannot grant on this platform, the hint names
`--unsafe` (trusted code only). A variable outside the allowlist gets a hint
that names `--allow-env` and never shows a value. Hints come only from the
worker's structured denial, so a program that panics with a denial's text
gets none.

**Differences from `--unsafe`.** With the same grant and host policy, a
program gives the same output and errors in both lanes, except:

| Topic | Default lane | `--unsafe` |
| --- | --- | --- |
| Output | shown when the program ends | streamed |
| Environment | only `--allow-env` names, from a snapshot of the caller's | the caller's whole environment |
| File writes | per-file and per-run quotas that return `Err` | no quotas |
| Examples | exact grant; deadline, output and write budgets and stdin shared with `main` | exact grant |
| Standard input | read in the worker, chunk by chunk (when enabled) | read on call |
| Hard limits | wall clock (kill), memory, CPU, file size where supported, processes | none; cooperative timeout and step limit |
| `process`, `serve` | refused | available |

### 9.12 App Mode (Interactive/Game Programs)

Programs that define `init`, `update`, and `render` functions (and no `main`)

user-defined functions are exempt from the `example` clause requirement.

The lifecycle functions have these signatures:

```geno
func init() -> State                     // Initial state
func update(state: State) -> State       // Called each frame
func render(state: State) -> Unit        // Draw the frame
```

Where `State` is a user-defined type.

The following always-available builtins support graphics and input. In
interpreter mode they are no-ops/stubs; in compiled JS output they drive a
canvas:

```geno
// Graphics
clear_screen(color)                      // -> Unit
```

## 10. Type Checking

### 10.1 Type Inference
Types are inferred for:
- `let` and `var` initializers when no explicit annotation is present
- Lambda return types, and lambda parameter types from context (section 7.6)
- `for` and comprehension variables, and tuple destructuring
- Generic type parameters

Function parameters and function return values require explicit type
annotations. Local `let` and `var` annotations are optional when the initializer
has an unambiguous type; explicit annotations are still accepted and checked.

### 10.2 Exhaustiveness Checking
Match expressions must cover all cases:
```geno
// Error: non-exhaustive, missing None
match opt with
    | Some(x) -> x
end match

// OK: wildcard covers remaining cases
match opt with
    | Some(x) -> x
    | _ -> 0
end match
```

### 10.3 Return Path Analysis
Functions must return on all paths:
```geno
// Error: else branch doesn't return
func bad(x: Int) -> Int
    if x > 0 then
        return 1
    else
        let y: Int = 0   // No return!
    end if
end func
```

### 10.4 Diagnostics and Fixes
Every diagnostic has a stable code (`spec.json` lists them) and the location of
the text it is about: an unknown method or field is reported at its name, not
at the receiver. Where the correction is unambiguous, the diagnostic also
carries a fix: a title and text edits that resolve it.

| Diagnostic | Fix |
| --- | --- |
| A name, method, field, type or constructor that is a likely typo of a single known one: one edit away (two for names of six letters or more), a swap of adjacent letters counting as one, with at most one changed letter and none in a name of four letters or fewer | Rename to the known one |
| Another language's name for an operation the receiver has: `len`, `size`, `str`, `upper`, `strip`, `startswith`, `chars`, `ord`, `chr`, `skip`, `items`, `has`, `put`, `flat_map`, `to_int` and similar | Rename to Geno's (`length`, `to_string`, `to_upper`, `to_chars`, `char_code`, `drop`, `entries`, `contains_key`, `insert`, `and_then`, `parse_int` or `float_to_int`, ...) |
| A positional call to a function with three or more parameters | Name each argument |
| `if c` or a loop header without `then` or `do`, or ending in `:` | Add the keyword at the end of the line, or replace the `:` with it |
| `end` without its block keyword on the same line | `end if`, `end for`, ... |
| `let mut x`, `True`/`False`, `"a" ++ "b"`, `elif`, `else:` | `var x`, `true`/`false`, `+`, `else if`, `else` |
| `&&`, `\|\|`, `!`, `=>`, `#`, `null` (also `nil`, `undefined`) | `and`, `or`, `not`, `->`, `//`, `None` |
| `lambda x, y: body` | `fn(x, y) -> body` |
| A function whose body ends with an expression of its return type | Add `return` before it |
| A call to `repeat_string`, `contains_substring` or `sort_strings` | Rename to the builtin that replaced it |
| An example expecting a panic after an arrow (E330, section 5.3.1): `-> panics`, `-> panics "m"`, `-> panic`, `-> panic("m")`; `example -> panic("m")` | The `panics` form: `example 1, 0 panics "m"`; `example () panics "m"` (none for `-> panic(e)` with a non-literal message) |
| `example panics` (E201) or `panics ""` (E202) | `example () panics`; delete the empty message |
| *Unreleased (proposal 0026):* `match x` or `match x:` without `with` | Add `with` |
| `type P = { x: Int, y: Int }` (also with `;` or a trailing separator) | `type P = P(x: Int, y: Int)` |
| `{ p with x = 1 }`, `{ p with x: 1 }`, `{ ...p, x: 1 }` | `p with (x: 1)` |
| `Point { x: 1, y }`, `Point { x: 1, ..p }` | `Point(x: 1, y: y)`, `p with (x: 1)` |
| `for i, x in pairs` | `for (i, x) in pairs` |
| An assignment to a variable declared with `let` | Declare it with `var` |
| `int_to_string`, `string_of_int`, `parseInt`, `parseFloat`, `string_to_int` and similar | `to_string`, `parse_int`, `parse_float` |
| A function without a return type whose `return` values have one type | Add `-> Type` with that type |

The hint in a "Did you mean" message names the nearest candidate even when it
is not close enough, or not unique enough, for a fix: a fix is attached only
when the correction is unambiguous. `docs/benchmark/seeded-mistakes.md`
measures how often the fixes repair common mistakes over the benchmark
corpus, and whether any repair changes what a program computes.

`geno.check()` returns the fixes with each diagnostic, `geno.fix()` applies them
until none is left and returns the fixed source with its check, the language
server offers them as quick fixes, and `geno check --fix` applies them to a
file.

## 11. Named Arguments Rule

Named arguments are required when a function has 3 or more required parameters,
or when a call supplies 3 or more arguments. For a method call, neither count
includes the receiver before the dot: `xs.fold(0, f)` writes two arguments
([proposal 0012](../proposals/0012-what-models-reach-for.md)). The three-argument
`range(start, end, step)` form is the positional exception:
```geno
// Definition
func make_rect(x: Int, y: Int, width: Int, height: Int) -> Rect
    ...
end func

// Call - MUST use named arguments
make_rect(x: 0, y: 0, width: 100, height: 50)

// Error: positional arguments not allowed for 3+ params
make_rect(0, 0, 100, 50)
```

This prevents argument ordering bugs common in LLM-generated code.

## 12. Example Program

```geno
type Tree[T] = Node(value: T, left: Tree[T], right: Tree[T]) | Leaf

func sum_tree(tree: Tree[Int]) -> Int
    requires true
    ensures result >= 0
    example Leaf -> 0
    example Node(5, Leaf, Leaf) -> 5

    match tree with
        | Leaf -> return 0
        | Node(value, left, right) ->
            let left_sum: Int = sum_tree(left)
            let right_sum: Int = sum_tree(right)
            return value + left_sum + right_sum
    end match
end func sum_tree

func main() -> Unit
    let tree: Tree[Int] = Node(
        10,
        Node(5, Leaf, Leaf),
        Node(15, Leaf, Leaf)
    )
    let total: Int = sum_tree(tree)
    print(total)  // 30
end func main
```

## 13. Compatibility

Geno remains pre-1.0, but accepted programs are not treated as disposable.

- Patch releases do not intentionally break programs accepted by the current
  versioned conformance corpus.
- A pre-1.0 minor release may change the contract only with an accepted design
  proposal, a changelog migration note, and an explicit conformance-corpus
  update.
- Stable features receive at least one minor release of deprecation before
  removal when security or correctness does not require an immediate change.
- Published diagnostic codes are never repurposed. A phase fallback may become
  a more specific code in a later release.
- Every release runs the current and retained previous-minor conformance
  corpora. While a next minor is in development, its development corpus
  (`conformance/v0.7` for this draft) runs after them and is not frozen.

The complete policy, including the status of tooling, standard-library, and
embedding surfaces, is in
[Compatibility and Stability](../operations/compatibility-policy.md).

## 14. Appendix: Grammar Summary

```ebnf
program     = (definition | import_stmt)* ;

definition  = func_def | type_def | type_alias | trait_def | impl_def
            | const_def ;

import_stmt = "import" TYPE_IDENT ;

func_def    = "async"? "func" IDENT type_params? "(" params? ")" "->" type
              effects?
              spec_clause*
              statement*
              "end" "func" IDENT? ;

type_params = "[" type_param ("," type_param)* "]" ;
type_param  = TYPE_IDENT (":" TYPE_IDENT ("+" TYPE_IDENT)*)? ;

type_def    = "type" TYPE_IDENT type_params? "=" "|"? variants ;

type_alias  = "type" TYPE_IDENT type_params? "=" type ;

trait_def   = "trait" TYPE_IDENT
              trait_method*
              "end" "trait" ;

trait_method = "func" IDENT "(" method_params ")" "->" type effects? ;

impl_def    = "impl" TYPE_IDENT "for" TYPE_IDENT
              impl_method*
              "end" "impl" ;

impl_method = "func" IDENT type_params? "(" method_params? ")" "->" type
              effects? spec_clause* statement* "end" "func" IDENT? ;
method_params = ("self" (":" type)? | param) ("," param)* ;

const_def   = "let" IDENT (":" type)? "=" const_expr ;
const_expr  = INTEGER | FLOAT | STRING | "true" | "false"
            | "-" (INTEGER | FLOAT)
            | "[" (const_expr ("," const_expr)*)? "]"
            | "(" const_expr ("," const_expr)+ ")" ;

params      = param ("," param)* ;
param       = IDENT ":" type ("=" expr)? ;

type        = simple_type | func_type | tuple_type ;
simple_type = TYPE_IDENT type_args? ;
func_type   = "(" types? ")" "->" type effects? ;
effects     = "with" effect_name ("," effect_name)* ;
effect_name = IDENT ;
tuple_type  = "(" types ")" ;
type_args   = "[" types "]" ;
types       = type ("," type)* ;

spec_clause = requires | ensures | example ;
requires    = "requires" expr ;
ensures     = "ensures" expr ;
example     = "example" ( exprs? "->" expr | exprs panics_tail ) ;
panics_tail = "panics" STRING? ;   // 0.7: "panics" is an IDENT, see 5.3.1

statement   = let_stmt | var_stmt | assign_stmt | index_assign | field_assign
            | compound_assign
            | if_stmt | while_stmt | for_stmt
            | match_stmt | return_stmt
            | break_stmt | continue_stmt | expr_stmt ;

index_assign = expr "[" expr "]" "=" expr ;
field_assign = expr "." IDENT "=" expr ;

break_stmt    = "break" ;
continue_stmt = "continue" ;

let_stmt    = "let" (IDENT | tuple_destruct) (":" type)? "=" expr ;
var_stmt    = "var" (IDENT | tuple_destruct) (":" type)? "=" expr ;
tuple_destruct = "(" IDENT ("," IDENT)+ ")" ;
assign_stmt = lvalue "=" expr ;
compound_assign = lvalue compound_op expr ;  // target contains no call
compound_op = "+=" | "-=" | "*=" | "/=" | "%=" ;  // adjacent characters
loop_binding = IDENT | loop_tuple ;
loop_tuple = "(" loop_element "," loop_element ("," loop_element)* ")" ;
loop_element = IDENT | "_" | loop_tuple ;
if_stmt     = "if" if_cond "then" statement* ("else" statement*)? "end" "if" ;
if_cond     = expr | "let" pattern ("|" pattern)* "=" expr ;
while_stmt  = "while" expr "do" statement* "end" "while" ;
for_stmt    = "for" loop_binding (":" type)? "in" expr "do" statement* "end" "for" ;
match_stmt  = "match" expr "with" match_arm+ "end" "match" ;
return_stmt = "return" expr? ;

match_arm   = "|" pattern ("|" pattern)* ("when" expr)? "->" statement+ ;

pattern     = wildcard | var_pat | ctor_pat | literal_pat | list_pat | tuple_pat ;
wildcard    = "_" ;
var_pat     = IDENT ;
ctor_pat    = TYPE_IDENT ("(" (patterns | named_pats)? ")")? ;
named_pats  = ".." | named_pat ("," named_pat)* ("," "..")? ;
named_pat   = IDENT ":" pattern ;
literal_pat = INTEGER | FLOAT | STRING | "true" | "false" ;
list_pat    = "[" pattern_elems? "]" ;
tuple_pat   = "(" pattern "," pattern ("," pattern)* ")" ;
pattern_elems = pattern_elem ("," pattern_elem)* ;
pattern_elem  = "..." IDENT? | pattern ;

expr        = or_expr ;
or_expr     = and_expr ("or" and_expr)* ;
and_expr    = not_expr ("and" not_expr)* ;
not_expr    = "not" not_expr | cmp_expr ;
cmp_expr    = bxor_expr (("==" | "!=" | "<" | ">" | "<=" | ">=" | "in" | "not" "in") bxor_expr)? ;  // non-associative
bxor_expr   = band_expr ("^" band_expr)* ;
band_expr   = shift_expr ("&" shift_expr)* ;
shift_expr  = add_expr (("<<" | ">>") add_expr)* ;
add_expr    = mul_expr (("+" | "-") mul_expr)* ;
mul_expr    = exp_expr (("*" | "/" | "%") exp_expr)* ;
exp_expr    = unary_expr ("**" exp_expr)? ;              // right-associative
unary_expr  = ("-" | "~") unary_expr | postfix_expr ;    // binds before **
postfix_expr = primary_expr (call | index | field | pipeline | with_expr | "?")* ;
                                    // field followed by call: a method call (7.5.1)
call        = "(" args? ")" ;
index       = "[" expr "]" | "[" expr? ":" expr? "]" ;
field       = "." (IDENT | INTEGER) ;   // INTEGER: a tuple field (7.9)
pipeline    = "|>" expr ;
with_expr   = "with" "(" named_fields ")" ;
named_fields = IDENT ":" expr ("," IDENT ":" expr)* ;

primary_expr = INTEGER | FLOAT | STRING | fstring | "true" | "false"
             | IDENT | TYPE_IDENT
             | list_lit | list_comp | tuple_lit | map_lit | if_expr | lambda
             | await_expr | typed_hole | "(" expr ")" ;

list_lit    = "[" exprs? "]" ;
map_lit     = "{" (expr ":" expr ("," expr ":" expr)* ","?)? "}" ;
if_expr     = "if" if_cond "then" expr ("else" "if" if_cond "then" expr)*
              "else" expr "end" "if" ;
list_comp   = "[" expr "for" loop_binding (":" type)? "in" expr ("if" expr)? "]" ;
await_expr  = "await" expr ;
typed_hole  = "?" IDENT ":" type ("where" expr)? ;
tuple_lit   = "(" exprs ")" ;
lambda      = "fn" "(" lambda_params? ")" "->" expr
            | "fn" "(" lambda_params? ")" "do" statement* "end" "fn" ;
lambda_params = lambda_param ("," lambda_param)* ;
lambda_param  = IDENT (":" type)? ;
fstring     = "f\"" (text | "{" expr (":" format_spec)? "}")* "\"" ;
format_spec = (CHAR? ("<" | ">" | "^"))? ("+" | "-" | " ")? "0"? INTEGER? ","?
              ("." INTEGER)? ("d" | "x" | "X" | "o" | "b" | "f" | "e" | "%" | "s")? ;

args        = arg ("," arg)* ;
arg         = (IDENT ":")? expr ;
```

> **Note:** In `panics_tail`, `panics` is the identifier `panics`, taken only
> directly after the inputs on the line of their last token; the optional
> `STRING` (not an f-string) is on the same line, and nothing else may follow
> on that line (section 5.3.1).

> **Note:** Statement labels on block closers (e.g., `end func name`) are
> optional and omitted from the grammar for brevity. A block closer's `end`
> and its keyword (`end if`, `end for`, `end func`, ...) are written on the
> same line; a bare `end` is an error (E201) whose fix adds the keyword.
